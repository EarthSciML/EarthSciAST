# The public, thread-safe right-hand side (`public_rhs_program`)

Fixtures for the program / workspace / forcing-set surface (issue #541, RFC U4).
API_SPEC.md §5.8, "The public right-hand side", is the surface; CONFORMANCE_SPEC.md
§5.51 is the gate. There are no right-hand-side numbers in this directory. Every
comparison is **bitwise** against the same binding's existing single-threaded
evaluation of the same Problem under the same compiler, `native` (Rust:
`debug_eval_rhs_into` with a scratch from `debug_new_scratch_taped`; Julia: the
Problem's `f!`), or against the same program's own serial results.

`manifest.json` is generated by `scripts/gen-public-rhs-program-manifest.py` from
the case table in that script. Edit the table and regenerate; consumers read only
the manifest.

## Who runs it

| Binding | Test file | What it does |
|---|---|---|
| Julia | `pkg/EarthSciAST.jl/test/conformance_public_rhs_program_test.jl` | every case, under `compiler = :native` |
| Rust | `pkg/earthsci-ast-rs/tests/public_rhs_program_conformance.rs` | every case, under `Compiler::Native` |
| Python | `pkg/earthsci-ast-py/tests/test_public_rhs_program.py` | builds the first case's Problem and asserts that `rhs_program`, `forcing_set` and `default_forcing_set` each raise `compiler_unavailable` |

TypeScript and Go have no simulator and do not run this suite.

Each binding reads `manifest.json`, iterates `cases` in order and dispatches on
`kind`. A kind it does not recognize is a test failure, not a skip. A
`document` path is relative to this directory; two cases point at existing
fixtures of other suites (`../missing_data/`, `../shaped_parameter_broadcast/`).
`options` are construction options: `runtime_array_parameters` is
`ProblemOptions::runtime_array_parameters` in Rust and the `esm_problem` keyword
of the same name in Julia. Every Problem is built with `compiler = native` and
`tspan = (0.0, 1.0)`; `prog = rhs_program(prob)`.

The tests that are not about a document — the static `Send`/`Sync` assertions,
the zero-allocation test, the workspace-identity and wrong-length errors — are
listed in CONFORMANCE_SPEC.md §5.51 and live in the same test file or beside it.

## The generator

Every input is drawn from one 32-bit hash, the same `h` as
`../range_restricted_rhs/` but keyed by a string that names what is drawn:

```
x = (fnv1a32(key) + 0x9e3779b1 * k) mod 2^32
x ^= x >> 16;  x = (x * 0x85ebca6b) mod 2^32
x ^= x >> 13;  x = (x * 0xc2b2ae35) mod 2^32
x ^= x >> 16
h(key, k) = x / 2^32
```

with every product and sum in unsigned 32-bit arithmetic and FNV-1a the 32-bit
variant (offset basis `0x811c9dc5`, prime `0x01000193`) over the UTF-8 bytes of
`key`. `generator.checks` lists `h` at a few `(key, k)` pairs; a binding asserts
its generator reproduces them exactly before it runs a case.

`<d>` below is a decimal draw number, `<v>` a state block's flattened name, `<n>`
a parameter's flattened name and `<s>` a forcing slot's flattened name. `k` is
the 1-based column-major linear index over the declared shape (1 for a 0-d
value).

| Input | Value |
|---|---|
| `u`, draw `d` | element `k` of block `v`: `0.5 + h("u<d>/<v>", k)`, placed at `v`'s offset in `state_layout` |
| `p`, draw 0 | `parameter_vector(prog, {})`: the defaults |
| `p`, draw `d ≥ 1` | `parameter_vector(prog, overrides)` with `overrides[n] = 0.5 + h("p<d>/<n>", 1)` for every parameter |
| `t`, draw 0 / `d ≥ 1` | `0.0` / `10 * h("t<d>", 1)` |
| `aux` | empty: every program here is whole-domain |
| set `D` | `default_forcing_set(prog)` / `prog.default_forcing()` |
| set `A` | slot `s`, element `k`: `0.5 + h("fA/<s>", k)`, one buffer per `forcing_slots` entry, in slot order |
| set `B` | `replace_forcing(A, replace_slot, buf)` / `A.replace(i, buf)`, `buf` element `k` = `0.5 + h("fB/<replace_slot>", k)` |

`draws.count` is 4. A **task** is a `(draw, set)` pair; the task list is every
draw with every set, in the order `(0, D), (0, A), (0, B), (1, D), …` (fault
case: set `D` only, then the `ok_state` with set `D`). Every `du` is prefilled
with NaN before a call.

## Checks every case runs

1. **Surface.** `n_states(prog)` equals `n_states`; `state_layout(prog)` equals
   `state_layout` (name, offset, shape; offsets here are 0-based, Julia adds 1);
   `parameters(prog)` equals `parameters` (names in this order, defaults
   bitwise); `forcing_slots(prog)` equals `forcing_slots` (name, shape and kind,
   in this order; Rust `SlotKind::Forcing` / `ArrayParameter`, Julia `:forcing`
   / `:array_parameter`).
2. **Default forcing.** Each buffer of `D` equals `default_forcing[slot]`
   bitwise (column-major). Two calls return sets with the same epoch.
3. **Epochs.** `D`, `A` and `B` have pairwise distinct epochs. Building `B`
   leaves `A`'s buffers and epoch unchanged. Building the same buffers into a
   second set gives a new epoch.
4. **Parameter vector.** `parameter_vector(prog, {})` equals the defaults in
   order. An override naming no parameter (`"NoSuchModel.nothing"`) is an error
   whose message names it.
5. **Equivalence (bitwise).** For every task, with one workspace used for all
   tasks in list order, the program's result equals the reference evaluation on
   the same `u`, `p`, `t` with the reference's forcing holding the set's data.
   Rust builds a fresh `debug_new_scratch_taped` scratch for each set after
   writing the set's buffers (as `ArrayD` of the slot's shape) into the forcing
   buffer through `forcing_handle()`. Julia evaluates `f!` of a reference Problem
   built with `param_arrays` mapping each slot name to the set's buffer reshaped
   to the slot's shape (for set `D`, the Problem as built, with nothing passed).
6. **History independence.** A second workspace evaluates every task in the
   order of ascending `h("order", i)` (`i` the task's 1-based position in the
   list; ties by `i`), then task 1 again: that last result equals a fresh
   workspace's result for task 1 bitwise.
7. **Concurrency.** Serial results for every task are computed first. Then
   `concurrency.threads` threads (Rust: OS threads; Julia: tasks spawned with
   `Threads.@spawn`), each with its own workspace and all sharing one program
   and the sets, make `calls_per_thread` calls: call `j` of thread `q` (both
   1-based) evaluates task `floor(h("c<q>", j) * n_tasks) + 1`. Every result
   equals that task's serial result bitwise.

## Case kinds

**`forcing`** — checks 1–7, plus:

- **Stale-forcing control.** With one workspace: evaluate draw 0 with `A`
  (`r_A`), then draw 0 with `B` (`r_B`). `r_B` differs from `r_A` in at least one
  element, and equals check 5's reference for `(0, B)`. Where
  `stale_control[binding]` is true the binding also runs the negative control on
  its old path: Rust builds one `debug_new_scratch_taped` scratch with `A`'s data
  in the forcing buffer, evaluates draw 0, overwrites the forcing buffer in place
  with `B`'s data (through `forcing_handle()`), evaluates draw 0 again on the same
  scratch, and asserts the second result equals `r_A` bitwise — the stale read
  the program exists to prevent. Julia builds the reference Problem with
  `param_arrays` holding `A`'s buffers, evaluates draw 0 with `f!`, overwrites
  the replaced slot's entry of `forcing_buffers(prob)` in place with `B`'s data,
  evaluates again, and asserts the same. (On `forcing_2d_gridded` Julia's `f!`
  reads `emis` only through the cached `col` and `frac`, which it refreshes on
  its process-global epoch, so the in-place write is not seen; on
  `forcing_1d_data_source` it reads the buffer live, so there is no stale result
  to reproduce and the manifest sets `stale_control.julia` false.) A negative
  control that does not reproduce the stale result is a test
  failure: the control has lost its teeth.

**`array_parameters`** — the Problem is built with `options`; checks 1–7 and
the stale-forcing control (without the negative control) as for `forcing`,
plus:

- **Baked twin.** Build the same document with `baked_twin.options`. Its
  `parameters` and `forcing_slots` are `baked_twin`'s (empty here). For every
  draw, its result with its own default set (zero slots) equals the run-time
  program's result with `D`, bitwise.

**`fault`** — checks 1–4 and 6–7 on the draws (set `D`, which has zero slots
here), plus:

- **Fault returned.** A workspace evaluating `fault_state` (states by name,
  placed by `state_layout`; `p` the defaults; `t = 0`) gets
  `RhsError::Fault { code, .. }` in Rust and a thrown `TreeWalkError` in Julia,
  with `code == expect_error.code`.
- **No latch.** The same workspace then evaluates `ok_state` without error, and
  its result equals a fresh workspace's bitwise.
- **Isolation.** In check 7, thread 1 evaluates `fault_state` on every call and
  gets the fault every time; every other thread runs the ordinary task list and
  gets no error and the serial results bitwise.
