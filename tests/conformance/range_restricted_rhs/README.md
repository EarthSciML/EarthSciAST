# Range-restricted, operator-restricted right-hand sides (`range_restricted_rhs`)

Fixtures for operator selection, tiles and lanes (issue #540, RFC U3).
API_SPEC.md §5.8, "Range-restricted right-hand sides", is the surface;
CONFORMANCE_SPEC.md §5.49 is the gate. Every check is **bitwise** against the
same binding's whole-domain evaluation of the same selected program under the
same compiler, `native`. There are no rhs
numbers in this directory: the reference for a tile or a lane is the binding's
own `select(prog; writes, terms)` evaluated over the whole domain.

`manifest.json` is generated by `scripts/gen-range-restricted-rhs-manifest.py`
from the case table in that script. Edit the table and regenerate; CI-side
consumers read only the manifest.

## Who runs it

| Binding | Test file | What it does |
|---|---|---|
| Julia | `pkg/EarthSciAST.jl/test/conformance_range_restricted_rhs_test.jl` | every case, under `compiler = :native` |
| Rust | `pkg/earthsci-ast-rs/tests/range_restricted_rhs_conformance.rs` | every case, under `Compiler::Native` |
| Python | `pkg/earthsci-ast-py/tests/test_range_restricted_rhs.py` | builds the first case's Problem and asserts that `rhs_program`, `select`, `halo`, `restrict` and `lanes` each raise `compiler_unavailable` |

TypeScript and Go have no simulator and do not run this suite.

Each binding iterates `cases` in order and dispatches on `kind`. A case kind the
binding does not recognize is a test failure, not a skip.

## The manifest

### Top level

| Field | Meaning |
|---|---|
| `compiler` | `"native"`. Every Problem in this suite is built with it. |
| `state` | How the global state is generated (below). |
| `fills` | `dead_halo`: the value written into storage cells outside `1..N` on a non-periodic axis (`NaN`). `du_prefill`: the value every `du` buffer holds before a call (`NaN`). |
| `cases` | The cases, each with an `id`, a `kind`, a `document` path relative to this directory, optional `metaparameters` (bound at `esm_problem`), and `covers` (the RFC test items it pins, informational). |

### The state

The global value of element `k` of state variable `v` is `0.5 + h(v, k)`, where
`v` is the flattened name (`"Chain.u"`), `k` the 1-based column-major linear
index of the element over the variable's full declared shape (1 for a 0-d
state), and

```
x = (fnv1a32(v) + 0x9e3779b1 * k) mod 2^32
x ^= x >> 16;  x = (x * 0x85ebca6b) mod 2^32
x ^= x >> 13;  x = (x * 0xc2b2ae35) mod 2^32
x ^= x >> 16
h = x / 2^32
```

with every product and sum taken in unsigned 32-bit arithmetic and FNV-1a the
32-bit variant (offset basis `0x811c9dc5`, prime `0x01000193`) over the UTF-8
bytes of `v`. The values lie in `[0.5, 1.5)`, so every quotient in the fixtures
is defined. Parameters keep their document defaults; `t` is `0.0`. The
global `u` and `aux` of a program are this state restricted to the program's
`u` and `aux` variables, in the program's layout.

### Selections

`selection` is `{"writes": W, "terms": T}`. `"all"` for `W` is every state of
the program; `"all"` for `T` keeps every contribution. Otherwise `W` is a list of
flattened state names and `T` a list of #539 origins, `{"component": "Adv"}` or
`{"coupling": 0}`, matched by equality.

### Boxes and decompositions

A decomposition is `{"axes": [{"index_set": "lon", "period": 16 | null}, ...],
"faces": [["lon_nodes", "lon"], ...]}`. A box is an object from index-set name
to an inclusive `[lo, hi]` pair in global, 1-based, unwrapped coordinates.
A tile is `{"owned": box, "storage": box}` naming every decomposed axis. Face
boxes are not listed: they follow from the cell boxes (owned faces are the owned
cells plus `N + 1` on the tile owning cell `N`; storage faces are the storage
cells plus one).

A halo report is a list of `{"variable", "index_set", "lo", "hi"}`, one row per
state variable the selected program reads and per decomposed or face index set
on that variable's shape. A binding compares the set of rows exactly.

### Case kinds

**`tile_partition`** — `selection`, `decomposition`, `halo`, `tilings`.

1. Build the Problem; `prog = rhs_program(prob)`; `op = select(prog; selection)`.
2. Assert `halo(op, decomposition)` equals `halo` exactly.
3. Evaluate `op` over the whole domain at the generated state into a
   NaN-prefilled `du`: this is `G`.
4. For every tiling and every tile in it: `restrict` (Rust: `tile`) `op` to the
   tile; read its layout; fill `u_S` and `aux_S` from the global state (an
   in-domain cell takes the global value; on a periodic axis a cell outside
   `1..N` takes the value at its wrapped index; every other cell takes NaN);
   prefill `du_S` with NaN; call it once.
   - Every owned row of `du_S` equals the corresponding element of `G`
     bitwise.
   - Every other element of `du_S` is still NaN.
   - `u_S` and `aux_S` are unchanged.
   - The layout is §5's: blocks in flat-layout order, each column-major over its
     storage box, bases contiguous from the start of the buffer.
5. Scatter every tile's owned rows into one vector; assert it equals `G`
   bitwise, and that every element was written exactly once.

A tiling with `"shared_storage": true` has every tile on one storage box. Its
tiles are called on ONE shared `du_S`, one after another, and the same checks
apply to the shared buffer once all have run.

The tilings of each case are `1x1`, `2x1`, `3x2` (`3` for a 1-D case), `narrow`
(the first tile owns `1..2` of the first axis, narrower than PPM's three-slab
low boundary band) and `rank_storage` (two tiles sharing the whole domain as
storage). Storage boxes are the owned boxes dilated by the halo, so on a
non-periodic axis they extend past `1..N` into dead cells.

**`tile_ok`** — one `tile`; the same per-tile checks as above.

**`tile_error`** — one `tile`; `restrict` raises `expect_error.code`. The other
fields of `expect_error` name what the message must mention (a variable, an
index set, the missing cells as `[lo, hi]` in unwrapped coordinates); a binding
asserts the code and that the message contains each named variable and index
set.

**`halo_ok`** / **`halo_error`** — `halo(op, decomposition)` returns `halo`, or
raises `expect_error.code`.

**`selection_sum`** — `operators` partition the program's terms. For each,
`select` with its `writes` and `terms` and assert its `aux` variables are
exactly `aux`, in flat-layout order. Evaluate each over the whole domain (`u`
holds its `writes`, `aux` its `aux`, both from the generated state) and the full
program `F` likewise. For every state element,
`|Σ_k G_k - F| <= rel * Σ_k |G_k|` with `rel = 1e-14`; a variable an operator
does not write contributes 0 to that operator's term. `contributions` records
the expected origins per equation, in order (the #539 corpus pins them; this is
a cross-check).

**`selection_error`** — `select` raises `expect_error.code`, naming
`expect_error.variable`.

**`selection_ok`** — `select` succeeds; `aux` is as given; every element of each
variable in `zero_rows` evaluates to `0.0` (a written variable whose kept
contributions are all dropped).

**`lanes`** — `lane_kind` (`"cells"` or `"columns"`), `lane_sets` (the index
sets a lane's `cells` column indexes, in order), `capacity`, `batches`,
`negative_control`.

1. `op = select(prog; selection)`; `G` as above.
2. Julia `lanes(op, kind, lane_sets)` with `kind` `:cells` or `:columns`; Rust
   `op.lanes(LaneKind::Cells { sets } | LaneKind::Columns { sets }, capacity)`.
3. For every batch: `cells` is a `capacity`-long list of global indices (each
   a `[lane_sets...]` tuple), stored as an `Int32` `[D, capacity]` matrix; `n`
   lanes are meaningful. Gather `u_L` and `aux_L` from the global state at those
   cells in the lane layout (API_SPEC §5.8); prefill `du_L` with NaN; call
   with `n`. For every lane `l <= n` and every element of every written
   variable, `du_L` equals `G` at `cells[:, l]` bitwise. Then fill the lane
   input buffers with `gather_lane_inputs!` and call the pre-gathered variant:
   the same equality holds.
4. Negative control: in the named batch, swap the `u_L` (and `aux_L`) inputs of
   the two named lanes (1-based) without swapping their `cells`; the bitwise
   comparison MUST fail for at least one of the two lanes.

`permutation_*` batches cover every cell (or column) exactly once in a seeded
random order; the last is padded past `n` with copies of a real cell. The
`duplicates_and_padding` batch repeats cells and pads with duplicates of a real
cell inside `n`.

**`lanes_error`** — `lanes` raises `expect_error.code`.

Every document validates against the schema and builds under Julia `native`
with a finite whole-domain right-hand side at the generated state. The expected
halo reports were derived from the rules and cross-checked by perturbing each
state element of the Julia native whole-domain right-hand side at three seeded
states and recording which elements of `du` moved. A halo counts reads, not
dependence: a read whose coefficient is an exact zero (the regional-inflow
slabs on a uniform grid) is invisible to perturbation but still in the halo.
