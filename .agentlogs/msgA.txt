fix(go): uppercase the LHS/RHS initialisms on UnitWarning

API_SPEC §8 row 19 recorded these two as the only §2.1 violations Go's
phase-6 audit found and did not fix, left open for a ruling.

Go's own house style had already ruled: FlattenedEquation.LHSString and
.RHSString spell the same two initialisms uppercase, so UnitWarning.LhsUnits
and .RhsUnits were the outliers rather than the precedent.

The wire contract is deliberately untouched and verified so. The
json:"lhs_units" / json:"rhs_units" tags are unchanged, as are the
"lhs_units" / "rhs_units" keys promoteUnitFindings writes into
StructuralError.Details; Julia, Python, Rust and TypeScript all carry the
same JSON spellings. A UnitWarning marshal -> unmarshal -> marshal round
trip is byte-identical before and after.

Struct fields are not manifest symbols, so api-surface.json does not move.

go build / go vet / gofmt clean; go test ./... 1396 passing before and after.
