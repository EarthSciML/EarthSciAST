A breaking release. The format moves to **esm 2.4.0**, and the Julia and Rust APIs changed in their maintainability passes. Every document that loaded under 0.14 still loads: the old spellings are read with deprecation warnings, and nothing is refused. Emit writes only the new names, so a document written by 0.15 declares `esm: 2.4.0`, which a 0.14 reader refuses. MIGRATION.md has the full tables. Read its two "esm 2.4.0" sections in Part IV first, then your binding's section.

## Breaking changes

### Format: esm 2.4.0

- **One operator type (#759, #768).** Expression templates are now **defined operators**. The block `operators`, `operator_imports` and the reference node `apply_operator` replace `expression_templates`, `expression_template_imports` and `apply_expression_template`. The old names are read as aliases, with the warning `deprecated_field` (blocks) or `deprecated_op` (node).
  - Every entry of an `operators` block is a definition of one operator. It gains the optional fields `defines` (the operator it defines, inferred when absent), `units` (a unit expression over its parameters) and `reference_only`. A `where` may be used without a `match`.
  - A call `{"op": N, "args": [...]}` resolves to a definition of `N` in scope, chosen by `priority`, then a definition with a `where` before one without, then declaration order. The call becomes a reference to the chosen definition. A name with no definition in scope is a placeholder; it is an error only if it is evaluated (`unlowered_operator`).
  - New load errors: `operator_arity_mismatch` (no definition in scope takes the call's operand count), `operator_defines_core_op` (a definition of a core op's name), and `definition_unit_mismatch` (a definition's body unit disagrees with its unit expression; a warning when the body unit cannot be determined). The error codes named after templates are renamed, and the old codes are aliases.
  - An operator-library file's `operators` may be empty. `lib/vector_calculus.esm` is a new library of this kind: it documents `grad`, `div`, `laplacian` and `curl` and defines none of them.
- **The spatial derivative is `partial` (#768).** `D` is only the time derivative. A `D` whose `wrt` is neither `"t"` nor the document's own independent variable, and the spellings `δ` and `∂`, are read as `partial` with `deprecated_op`. A `D` whose `wrt` names the document's independent variable is read as `wrt: "t"`. `partial` and `integral` have fixed unit expressions, so an unresolved call still has a determinable unit.
- **`grad`, `div` and `laplacian` are ordinary operator names (#766).** No binding treats them specially in classification, units or code generation. Write a spatial derivative with `partial`, or lower the name with your own rule.
- **The `pde` system kind is gone (#766).** `system_kind` derives `sde`, `nonlinear` or `ode`. A declared `"pde"` loads with the warning `deprecated_system_kind` and is ignored. Go's `ApplyDAEContract` now runs on models that have spatial derivatives. A spatial derivative on an equation's left-hand side is now refused with `E_NONTRIVIAL_DAE`, as Rust already refused it.
- **Rules write references; nothing is inlined (#755, #766).** A firing `match` rule writes a reference to itself instead of its expansion. Rules rewrite definition bodies once per instance, and the elementwise lift and mount edges keep references. This replaces eager expansion. Which rules fire can differ in four edge cases (esm-spec, top of the 2.4.0 notes). None of them occurs in the 2026-11 corpus of real models.

### Bindings

- **Julia (#752).** The maintainability campaign changed the public surface. `validate(path)` is now `validate_path(path)`. The deprecated `build_evaluator` alias is removed. The undocumented `BuildInspection` fields are gone. `notify_forcing_refresh!` takes the Problem. `build_refresh_callback` needs `owner`. Every exported error type renders one way and leads with a `code` field, read with `error_code` / `error_message` / `error_path` / `error_file`. Several `ArgumentError`s are now typed errors (`FlattenError`, `SimulateError`, `ParseError`). MIGRATION.md, Part III, Julia, lists every row.
- **Julia: template references are compiled, never expanded (#754, #765).** The build compiles each reference as a call and refuses, with the reason, one it cannot compile. Nothing falls back to expansion.
- **Rust (#748).** The maintainability pass removed about 10,000 lines.
  - Removed: the `performance` module and its Cargo features (`parallel`, `simd`, `zero_copy`, `custom_alloc`, `performance`, `cli`); the deprecated `Compile` alias; never-constructed error variants; and the `debug_*` right-hand-side seams.
  - Providers are now one `DataProvider` trait keyed by the parameter each one feeds.
  - Every build flattens first. The §6.6.2 key rules apply to `p`, `const_arrays` and providers, as they already did in Julia and Python.
  - Coded load and build refusals keep their code (`SchemaDiagnostic`, `StructuralDiagnostic`, `CodedBuildError`).
  - MIGRATION.md's two Rust "0.15.0" tables list every row.
- **`esm` tool (#748).** The subcommands `analyze`, `coupling-analysis`, `performance-profile`, `optimize`, `compare`, `init`, `benchmark` and `schema-check` are removed. Use `info`, `graph`, `units`, `diff` and `validate`.

## New

- **Markdown and Typst source documents load from files (#760, esm-spec §1.2.1).** A loader picks the format by file extension (`.md`, `.typ`, anything else JSON) for the root document and at every reference site: mounts, operator imports and coupling imports. Conformance tier `tests/conformance/source_documents/`. Rust's `canonical_expand` example reads by extension too (#764).
- **Expressions inside path blocks print as math (#761).** Test assertions, event conditions and affects, guesses, parameter-update expressions and coupling expressions inside `#esm-block(...)` / ```` ```esm:<path> ```` blocks print as `$…$` math instead of JSON, and are read back.

## Fixes

- **Rust: time-varying data-fed parameters reach the build-time observed pass (#762).** `esm test` with `--features esio` failed with `E_TREEWALK_UNBOUND_NAME` on an unknown defined from a record-shaped data-fed parameter.
- **Rust:** a `num-bigint` 0.5 bump broke the build; it is pinned to 0.4 (#756). Build-time values take the tape on wasm32 as well (#758).
- **Python, Go, TypeScript:** reaction systems' data-fed parameters are collected after the models' parameters, as Rust and Julia already do (#756). Rust: an undeclared elementwise result over disjoint index sets spans their union (#756).
- **Julia: a tile that shares its code read template array arguments at the wrong slots (this release).** A state array bound to a template's array parameter carried a base slot from the whole-domain layout, so a code-sharing tile of a `restrict`ed program read the wrong cells. Bounds-checked runs (Julia 1.10 CI) threw `BoundsError`. Unchecked runs could give a wrong derivative at a tile's end cell.
- **Python: an operator library with an empty `operators` block validates and round-trips (this release).**

## Performance

- **Julia: one const-table wrapper per build (#769).** Cells reading the same table merge into one kernel. Before, an out-of-place build of an N-cell table read produced N kernels.
- **Julia: shared subexpressions are handled once (#770)** in round 1 of the kernel-class merge and in the direct StableHLO emitter. Before, walks were exponential in template nesting depth.
