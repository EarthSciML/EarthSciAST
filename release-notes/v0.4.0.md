A breaking release. The `.esm` format moves to **esm 1.3.0**, and documents written for 1.2.0 and earlier load unchanged. The breaks are in the Rust and TypeScript flatten types, in documents that mix binary32 and binary64 across a mount, and in the last bits of reverse scans. Each one is listed below with how to upgrade.

## Breaking changes

- **Rust: `FlattenedSystem` has two new public fields**, `equation_contributions` and `equation_lifted` (#555). Code that builds a `FlattenedSystem` with struct-literal syntax must set both. `Vec::new()` for each is accepted and means no provenance recorded. Better, take the system from `flatten` and modify it.
- **Rust: `FlattenError` has a new variant**, `ContributionsOutOfStep` (#555). It is raised when either new list is non-empty and its length differs from the number of equations. A `match` over `FlattenError` without a `_` arm needs one more arm.
- **TypeScript: `FlattenedEquation.contributions` is required** (#555). Code that builds a `FlattenedEquation` by hand must supply it. `[{ expr: rhs, origins: [] }]` is the neutral value.
- **Precision now crosses a mount** (#532). A mounted document's `domain.element_type` used to be dropped, so a `"Float32"` leaf ran in its mounter's precision without any warning. Now the leaf keeps its declared precision. As a result:
  - Combining one of the leaf's binary32 variables with a binary64 variable of the mounting document, in an equation or a coupling, is now the `mixed_element_type` error.
  - Julia and Python refuse a binary32 variable they would compute in binary64 (`float32_unsupported`), instead of returning a binary64 answer.
  - A reaction-system leaf whose precision differs from its mounter's is refused with the new `element_type_uncarried`.

  To upgrade, declare the same `element_type` in both documents, or convert explicitly at the coupling.
- **Reverse scans fold from the top** (#549). A `>=` or `>` scan, or a mirrored `i <= j` or `i < j` scan, now sums from the highest `j` down. All bindings and both compilers now give bit-identical results. Before, Python's dense path summed pairwise. Forward scans are unchanged. Saved references for reverse scans may move in the last bits.

## Highlights

- **`solver.external`** (esm 1.3.0, #554): an optional reference to an external run-configuration document. Every binding parses, validates and round-trips it, and resolves where it points without opening the file.
- **`solver.time_span`** (esm 1.3.0, #556): the interval a document is meant to be simulated over. Each bound is either seconds or an RFC 3339 UTC timestamp. `resolve_time_span` converts a timestamp to seconds and gives the same binary64 value in all five bindings.
- **Per-term provenance through flatten** (#555). Each flattened equation lists the terms that make up its right-hand side and which component or coupling entry wrote each one. Canonical JSON, equality and hashing are unchanged.
- **Native covers more shapes** (#549, #551): `makearray` regions whose value is a prefix scan, contractions over ragged ranges, overlap joins in construction-time observeds, and nested scalar reductions inside a `makearray` region (Julia).
- **Rust native holds far less memory on join-heavy documents** (#537), back to 0.2.0's footprint, with bit-identical results.
- **A generated cross-language API reference and runnable usage guides** (#531).
