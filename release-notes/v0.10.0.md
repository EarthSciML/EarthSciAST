A breaking release. It breaks Rust code that builds or destructures a `ValueInventionError` or builds a `ProblemOptions` literal without `..Default::default()`, code that reads the `details` of a `circular_dependency` diagnostic, documents that mount the standard library's `lib/calendar.esm` or `lib/interp.esm` as a subsystem, and Julia code that relies on the flattened equation order of an `operator_compose` merge owned by a later component. The `.esm` format stays at **esm 1.3.0**, and `esm-schema.json` is unchanged. Most documents that loaded under 0.9.0 still load and validate; the exceptions are a cycle among observeds that crosses a model–subsystem boundary, which is now `circular_dependency` (and is refused at load by Rust and Python), and a document that mounts `lib/calendar.esm` or `lib/interp.esm`, whose contents changed (below). Some documents that flattened or built under 0.9.0 are now refused: a pointwise lift whose right-hand side reads an operand over an index set the grid does not run over, a Julia `shape: []` variable whose definition is an array, and (Rust) a value-invention key that evaluates to NaN. One rule is relaxed: two models that read each other's states are no longer a `circular_dependency`.

## Breaking changes

- **`circular_dependency` is a cycle among observeds, not among models** (esm-spec §4.9.7, new). The check used to count any scoped read between two top-level models as a dependency, so two models whose equations read each other were refused, in every binding's `validate()` and at load in Rust. Only a read inside an observed's definition orders two computations; a read of a state or a parameter never does. The graph is now the §4.9.6 observed graph extended over the whole document: its nodes are the observed unknowns of every model and subsystem at every depth, by full scoped name, and references resolve own names first, then relative to the model's own subsystems, then at top level (§4.8.4).
  - **Now valid:** two models whose state equations read each other's states, and a state equation that reads another model's observeds whose definitions read that state (`tests/valid/cross_model_state_reads.esm`, `cross_model_mixing_observed_state_cycle.esm`, `cross_model_observed_reads_no_loop.esm`).
  - **Now refused:** a cycle that crosses a model–subsystem boundary, such as a model's observed and its subsystem's observed reading each other (`tests/invalid/circular_coupling_subsystem.esm`). No binding reported it before. Rust's load-time check now also runs on a single model with subsystems, and Python re-runs it after resolving `{"ref"}` mounts and in typed `validate()`.
  - **The diagnostic changed shape.** `details.cycle` lists scoped variable names (`["ModelA.a", "ModelB.b", "ModelA.a"]`) where it used to list model names, and `details.coupling_chain` is gone. The message reads "Circular dependency among observeds: …". The search order is pinned (code-point order of scoped names), so every binding names the same cycle. A cycle inside one scope is still `observed_cycle`.
- **`lib/calendar.esm` and `lib/interp.esm` are template libraries** (esm-spec §9.7.1). They used to be subsystem models: `Calendar`, with a `t_utc` parameter and observeds `year` … `seconds_since_midnight` and `fractional_year`, and `Interp`, a copy-paste demonstration. A document that mounts either file as a subsystem now fails to resolve it. Import the templates instead, with `expression_template_imports` (`{"ref": "esm:std/calendar.esm"}`, below) and `apply_expression_template`, binding the template parameter `t` to your time variable: `{"op": "apply_expression_template", "args": [], "name": "day_of_year", "bindings": {"t": "t_utc"}}`. `fractional_year` and the `s_per_*` / `rad_per_day` bridge parameters have no template (`lib/solar.esm` computes its own fractional-year angle, `gamma`). `lib/solar.esm` keeps its interface and now imports the calendar templates instead of calling `fn datetime.*`, so for `|t_utc| ≥ 2^52` s (about ±142 million years) its calendar fields are NaN.
- **A pointwise lift reads each shaped operand by index-set name** (esm-spec §4.3.4), in every binding. When `flatten` lifts a state onto an operator's grid (esm-spec §10.5), each axis of a shaped operand in the lifted right-hand side is now read at the loop that runs over that index set: a `[lev]` profile in a `[lon, lat, lev]` lift becomes `index(p, k)`, and a `[lev, lat, lon]` field becomes `index(m, k, j, i)`.
  - Julia, Python, TypeScript and Go used to index every shaped operand at all of the grid's loops in loop order, which read the wrong cells for an operand of lower rank or permuted axes. Rust used to index only the lifted state and loaded fields, leaving other shaped variables (an air-mass state, say) as bare whole-array names in the per-cell `faq` body.
  - **Now refused** with the binding's dimension-promotion error (`DimensionPromotionError`, Rust `FlattenError::DimensionPromotion`): an operand axis on an index set the grid does not run over (a staggered `lev_edge`, a coarser set), an index set repeated in an operand's shape or on the grid, and an array operand under `reshape`, `transpose` or `concat`. Such a document used to flatten to a wrong right-hand side.
  - An operand that shares no index set with the grid and is an argument of a non-elementwise op (a `fn` lookup table, say) stays whole, as before.
- **Julia: an `operator_compose` merge owned by a later component moves to that component's equations** (esm-libraries-spec §4.7.1 step 4 and §4.7.5 step 4, "Ordering"). When an operator declared before the owning component writes `D(Chem.B, t)`, the merged equation now goes after the last equation of `Chem` and of every component declared before it, as Python, Rust, TypeScript and Go already did. Julia used to leave it at the operator's position, so its flattened equation order, and with it the positional parameter and state vectors, differed from the other bindings. The spec now states this placement; `tests/conformance/flatten/` gains a `compose_position` tier.
- **Julia: an explicit `shape: []` is a declared scalar.** `promote_downstream_shapes` used to treat `shape: []` like an absent shape and promote it to the shape its definition infers. Only a variable with no `shape` is promoted now; a `shape: []` variable whose definition is an array (or a `faq` over inline ranges) throws `DimensionPromotionError` with `array_shape_mismatch`, naming the variable and the inferred shape.
- **Rust: a NaN value-invention key is refused.** A `distinct` key or `join` column that evaluates to NaN used to invent a member silently. It is now `value_invention_key_out_of_range` (below). `floor` and `ceil` also keep a NaN or infinite value as a float instead of casting it to an integer.
- **Rust: `ValueInventionError` is a struct** `{ message: String, code: Option<&'static str> }`, built with `ValueInventionError::new(message)` or `ValueInventionError::with_code(code, message)`. It was a tuple struct `ValueInventionError(String)`; code that builds it or reads `.0` must be updated. Python's `ValueInventionError` gains a `code` attribute without breaking callers.
- **Rust: `ProblemOptions` has a new field, `rewrites: CompilerRewrites`.** It is hidden from the documentation and defaults to every compiler rewrite on. A `ProblemOptions` literal that does not end in `..Default::default()` must set it.
- **Python: `validate()` checks `faq` expressions in inline subsystems.** The aggregate checks (undeclared index sets and template-bound index-set names among them) used to walk top-level models only. They now walk inline subsystem models at every depth, as Julia's do, so an error in a subsystem's `faq` that Python used to miss is reported.

## New

- **`esm:std/<file>.esm` references to the standard library** (esm-spec §4.7, "Standard-library references"). A ref of this form resolves, at load, to the copy of the repository's `lib/` directory that each binding now bundles in its package (Julia `data/lib/`, Python `earthsci_ast/data/lib/`, Rust `src/stdlib/`, TypeScript a generated module, Go an embedded directory). Every binding must support it, at every site that takes a §4.7 ref: subsystem mounts at both forms, template imports (§9.7.2) and coupling imports (§10.10). It needs no network access and does not depend on where the referencing file lives, so a document loaded from a string can write `{"ref": "esm:std/interp.esm"}`.
  - The `esm:` scheme is reserved: such a ref is never resolved as a path or a URL.
  - An unknown name (`esm:std/nope.esm`) or any other spelling under the scheme (`esm:std/sub/x.esm`, `esm:other/x.esm`) is the mechanism's ordinary unresolved diagnostic: `template_import_unresolved`, `coupling_import_unresolved` or `unresolved_subsystem_ref`.
  - `${VAR}` is not expanded inside the form. A relative ref inside a bundled file names a sibling bundled file. The authored `ref` round-trips verbatim.
  - The Rust `esm` CLI's validator resolves it, and the Rust crate exposes the bundle as `extension::stdlib::{bundled_file, bundled_names, resolve}`.
- **Pure-AST standard-library templates.** Each is written with core ops only and checked against the built-in form it stands for in every binding that can evaluate it. **The built-in forms (`fn`, `table_lookup`, the polygon leaves, `argmin`, `argmax`, `skolem`, `rank`) are unchanged and still supported.**
  - **`lib/interp.esm`**: `searchsorted(x, xs, n)`, `linear(table, axis, x, n)` and `bilinear(table, axis_x, axis_y, x, y, nx, ny)`, the axis lengths given as integer parameters. On every success scenario of `tests/closed_functions/interp/` each gives the bits of the matching `interp.*` function, NaN queries included (esm-spec §9.2). They do not repeat the functions' load-time axis checks.
  - **`lib/calendar.esm`**: `year`, `month`, `day`, `hour`, `minute`, `second`, `day_of_year`, `julian_day`, `is_leap_year` and `seconds_since_midnight`, each a template of one parameter `t` (UTC seconds). For finite `|t| < 2^52` s each equals the matching `datetime.*` function bit for bit; outside that domain, and for NaN or infinite `t`, each returns NaN where the function answers or raises `closed_function_overflow` (esm-spec §9.2).
  - **`lib/geometry.esm`** (new): `overlap_area_planar` and `overlap_area_spherical`, the overlap area of two convex polygons from ring stacks, standing for `polygon_intersection_area` with `manifold: "planar"` and with `"spherical"` / `"geodesic"` (steradians), and `lonlat_to_unit` to build unit-vector stacks (esm-spec §8.6.1). Padding vertices contribute exactly zero and either orientation is accepted. Unlike the leaf, a ring with no extent gives 0 rather than an error, and non-convex input is not checked. The collinearity tolerances are stated in §8.6.1.
  - **`lib/relational.esm`** (new): `argmin(f, n)` / `argmax(f, n)` (smallest index wins a tie; a NaN candidate wins at its first occurrence, where the op skips a NaN after the first), `argmin_where` / `argmax_where` (only candidates passing a predicate compete; `n + 1` when none does), `pair_key` / `edge_key` (a composite key as one integer, NaN when a component is out of range or not an integer), and `rank_of` / `rank_of_set` (a 1-based rank, computed as a count). See the "Composition" paragraphs under esm-spec §4.2, "Relational / value-invention & geometry".
  - `docs/content/standard_library.md` documents each template. New conformance tiers: `interp_templates`, `datetime_templates`, `relational_templates` and `geometry_templates`.
- **A template parameter may name a `faq` range's index set** (esm-spec §9.6.1). In a template body, `"ranges": {"k": {"from": "S"}}` instantiated with `"S": "edges"` becomes `{"from": "edges"}`, a derived set included. An expanded `from` that names no declared index set is `undefined_index_set` at the call site. The spec also now states what all five bindings already did: a parameter in a dense `ranges` tuple (`[1, "n"]`) is substituted, and its value must be an integer literal or a metaparameter expression.
- **Value invention accepts integer keys** (esm-spec §9.6.6). A `distinct` `key` may be any integer-valued expression, not only a `skolem` tuple, and a `join.on` column may be a plain observed integer column, with several `on` pairs per clause. Julia, Python and Rust evaluate it; Go and TypeScript accept it.
- **`value_invention_key_out_of_range`**, a new diagnostic (esm-spec §9.6.6). A `distinct` key or a value-invention `join` column that evaluates to NaN at build is refused, naming the column and the loop indices. It takes precedence over `derived_index_set_unmaterialized`. Julia, Python and Rust raise it; Go (`CodeValueInventionKeyOutOfRange`) and TypeScript register the code.
- **An unshaped `ifelse` with one array branch has the array's shape** (esm-spec §4.3.4). A variable with no `shape` whose definition is elementwise down to an `ifelse` with a scalar condition, one array branch and one scalar branch, such as `X = ifelse(lev < 2, F * 2, 0.0)` with `F` over `cell`, is a `cell`-shaped array whichever branch is taken. The Rust interpreter used to give it the taken branch's rank, so a gather from it faulted or read NaN, and the Rust native compiler refused it. Rust now builds it natively and agrees with Julia and Python; `flatten`'s output still carries only the declared `shape`. `shape: []` still declares a scalar, which cannot hold the array branch.

## Dependencies

- **Rust:** the `s2rst` pin moves from `=0.5.0` to `=0.5.1`.

## Other changes

- **A `const` node's `value` is written in canonical-number form in every binding** (CONFORMANCE_SPEC §5.5.3.1 rule 1). Rust and Python used to write a table authored `[100.0, 200.0]` back as `[100.0,200.0]`, and Julia wrote a lowered `table_lookup` as `10.0`; all three now write `[100,200]`, as TypeScript and Go already did. The value in memory is unchanged.
- **Julia: integers in JSON arrays read as integers.** An integer that followed a float in the same JSON array used to be read as a float; it now reads as an integer, as in the other bindings.
- **Julia: a gated conservative overlap regrid over a live source field builds.** A regrid gated by `conservative_overlap_*_gated` whose source field is a live array (`param_arrays`, or a data-fed parameter bound to a forcing buffer) used to fail with `E_TREEWALK_JOIN_OVERLAP` because the right-hand-side gate resolver read only 1-D envelope factors. It now builds under the interpreter and under `native`, from `esm_problem` and from `rhs_program`. A live gather's loop-counter subscript may now also contain `mod` and a quotient under `floor` or `ceil`. An envelope factor list of any other length, or a factor whose rank does not match its list, is an `E_TREEWALK_JOIN_OVERLAP` error, and an envelope factor that is not build-time data gets the CONFORMANCE_SPEC §5.5.6 diagnostic instead of a bare `KeyError`. CONFORMANCE_SPEC §5.5.6 now describes the one-name ring envelope form correctly.
- **Rust: `interp.bilinear` and `interp.searchsorted` take an array-valued query.** With one query per cell, the interpreter used to evaluate only `interp.linear` and return NaN for the other two, and the native compiler refused them. All three now evaluate per cell, bit-identical to Julia.
- **Rust: reads of a derived index set's `member_factor` build under strict `native`.** The compile route used to size a derived set but leave its member factor at its scalar default; it now binds it to the invented member ids, as the build pipeline does.
- **Rust: the build pipeline fills a declared shape from a single value.** An observed with a declared shape of more than one element whose definition evaluates to a single value now fills the whole shape (esm-spec §4.3.4), as the compiled route does; it used to be materialized at shape `[1]`.
- **Rust: `[join-gate]` diagnostics print only when `ESS_JOIN_GATE_LOG` is set.** The interpreter used to write them to stderr unconditionally. The tape builder now writes a matching line for each gated tuple-list contraction.
- **Go: a derivative of an expression no longer makes its operands states.** `D(a + b) ~ 3` used to classify `a` and `b` as states in Go; it no longer does, as in Python.
- **Faster native builds and evaluation.** Both native compilers (Rust tape, Julia native) recognise a sum of `ifelse(a[k] <= x, 1, 0)` and its mirrored and swapped spellings as a count, with a binary search on a constant non-decreasing axis, so each standard-library interpolation template compiles to one count per axis. Julia native computes a repeated sub-tree once. Rust interns identical constants, numbers values per scalar rule, lets every join gate between two contracted indices restrict a gated walk (CONFORMANCE_SPEC §5.24.2), evaluates a sparse join-gated `faq` at its candidate cells only, and shares a large folded contraction's inputs across its chunks instead of copying them per chunk. Join-heavy documents that stalled for hours in the Rust tape builder now build in minutes. Every rewrite gives the same bits as the lowering it replaces. The Rust XLA backend also lowers the compacted gated `faq` and the count rewrite.
