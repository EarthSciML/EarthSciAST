A breaking release. It breaks Rust and TypeScript code that builds a flattened system's loader fields, Rust code that builds a `DataSourceBinding` literally or matches every `FlattenError` variant, Python code that relies on `load` raising on a unit error, and Julia and Rust callers of `esm_problem` whose run-time providers deliver a sample of the wrong shape or are keyed ambiguously. The `.esm` format stays at **esm 1.3.0**. Every document that loaded under 0.8.0 still loads. Some that validated or flattened under 0.8.0 are now refused: a `variable_map` whose `from` names a data source's field, a scalar data-fed parameter mapped onto a shaped one, a unit error that Julia and Go used to miss, and a document that asks a data source for two records per sample in a way the source or the parameter's shape cannot deliver (§8.5.1, below). One schema rule is relaxed: a `data`-fed parameter no longer has to declare a `shape`.

## Breaking changes

- **`LoaderField` gains the effective `records_per_sample`** (esm-libraries-spec §4.7.5, "Loader fields"). Every binding's loader-field entry now says whether the field holds one record or the pair that brackets the query time.
  - **Rust:** `LoaderField` has a new public field `records_per_sample: u8`. Code that builds the struct literally must set it. Deserializing an older serialized `LoaderField` still works: the field defaults to 1.
  - **TypeScript:** `LoaderField.recordsPerSample` is a new required field. Code that builds a `LoaderField` object must set it.
  - Julia (`records_per_sample`, a keyword argument defaulting to 1), Python (`records_per_sample`) and Go (`RecordsPerSample`) add the field without breaking existing callers.
- **Rust: `DataSourceBinding` and `DataSourceTemporal` gain `records_per_sample: Option<u8>`.** Code that builds a `DataSourceBinding` literally must set it. `DataSourceTemporal` implements `Default`, so a literal ending in `..Default::default()` still compiles.
- **Rust: two new `FlattenError` variants.** `FlattenError::RecordsPerSample(DiagnosticError)` is raised when `flatten` refuses a record shape with `records_per_sample_invalid` (below), and `FlattenError::VariableMapShapeConflict { from, to, source_shape, target_shape, took_shape }` when a data-fed `variable_map` source's shape disagrees with its target's (below). A `match` on `FlattenError` with no wildcard arm must handle both.
- **A data-fed `param_to_var` source keeps its own declaration** (esm-libraries-spec §4.7.3). When a `param_to_var` or `conversion_factor` coupling maps a data-fed parameter (a `data` rule with a `from` binding) onto a parameter of another component, the parameter that survives is the source's own: its units, `default`, `description`, `update` and `distribution`. Every binding now does the same thing here.
  - **Python, TypeScript and Go** used to drop the `update` when the data source was keyed with the same name as the owning model, rebuilding the parameter from the target's fields. It then disappeared from `discrete_parameters` while `loader_fields` still listed it. It now keeps its `update`.
  - **Shape.** The rewritten equations index the source the way the removed target was declared, so a source with no `shape` takes the shaped target's shape. A source that declares a `shape`, `[]` included, must declare the target's: the same index sets in the same order. A shapeless source mapped onto several shaped targets must find the same shape on all of them. `flatten` refuses anything else, in any coupling order, with `VariableMapShapeConflictError` (Rust `FlattenError::VariableMapShapeConflict`). Under 0.8.0 a scalar source mapped onto a shaped target flattened, and its equations then indexed a scalar. To fix such a document, remove the source's `shape` key or declare the target's shape.
  - **A data source is not a coupling endpoint** (esm-spec §8). A `variable_map` whose `from` names a data source's field that no component declares is now an unresolved reference, `unresolved_scoped_ref` at `/coupling/<i>/from`. Python, TypeScript and Go used to accept it under a rule left over from before esm 1.0.0, and Rust refused it at load. The field is reached through the data-fed parameter that names it in `update.from`.
- **Stricter unit checks in Julia and Go** (esm-spec §4.8). Julia's and Go's unit checkers stopped walking a product at its first factor whose unit they could not determine, such as a bare literal, so `1000 * exp(T)` with `T` in degC passed while Rust, Python and TypeScript rejected it. Both now walk every factor, so a finding in any later factor is reported: `2 * x * log(T)`, `0.5 * sin(L)`, and the same shapes inside a sum, a quotient or a power. Julia also now checks the argument of `sign`, so `sign(exp(T [K]))` is an error.
- **`sign` is dimensionless in every binding** (esm-spec §4.8.3 gains a `sign` row). Its result is `-1`, `0` or `+1` whatever its argument's unit, and its argument is still checked for the findings inside it. Go, Rust and TypeScript used to give `sign` its argument's unit, so `sign(v [m/s]) * L [m]` came out as `m^2/s` there and `m` in Julia and Python. A document that relied on the old Go, Rust and TypeScript result now gets a unit error.
- **Python: `load` no longer checks units; `validate()` reports every unit error.** `load()`, `load_path()` and `load_string()` used to raise on some unit defects, and the check they ran looked only at a bare-variable argument of a transcendental function, so `exp(-Ts_c - 4)`, `log10(p_a + p_b)` or `tanh(x / tau)` in the same file went unreported. Python now has one unit checker, in `validate()`, like the other four bindings. A document whose only defects are unit defects loads, and `validate()` reports each defect once, as a `unit_inconsistency` or `unit_parse_error` error with its JSON Pointer, at the same codes and paths as the other bindings. Code that relied on `load` raising must call `validate()` and check `is_valid`. `validate_text` and `validate_path` no longer raise; a failure inside `validate()` also becomes a result.
- **Julia and Rust: `esm_problem` refuses a provider sample of the wrong shape.** A sample whose dimensions are not the parameter's declared shape, axis by axis, used to be bound as given; a transposed or reshaped sample is now refused (Julia `DimensionMismatch`, Rust `ProviderError`). This covers const and discrete providers, extent discovery, and every refresh, wherever the declared shape resolves before the build.
- **Julia and Rust: run-time providers are routed by name like `parameter_overrides`** (esm-spec §6.6.2). A provider passed to `esm_problem` feeds the parameter its key designates: `Fed.s` is exact, and a bare `s` or partial qualification designates the one parameter that carries it. An exact key wins over a bare key for the same parameter. These are now refused: two non-exact keys for one parameter, a key that two parameters carry, and a provider and a `const_arrays` entry for the same parameter under any spellings (Julia also refuses a `param_arrays` entry).
- **Rust: `providers_from_document` runs on the model clock** (esm-spec §2.2.7). Model time 0 is `domain.temporal.reference_time`, else `domain.temporal.start`, else the run window's start, else the Unix epoch, and a sample at model time `t` reads that origin plus `t`. A caller that sampled a document with a `domain.temporal` block in Unix seconds must now pass model seconds. `EsioProvider::sample_with_selection_at` takes model seconds. Julia's and Python's `providers_from_document` use the same clock.

## New

- **`from.records_per_sample` on a `data` rule** (esm-spec §8.5.1). `1` delivers the record at or before the query time; `2` delivers that record and the next one, stacked along the parameter's first declared dimension, which must be an index set of exactly two members. The source does not interpolate; the model blends the pair itself. The effective value is the rule's own field, else the source's `temporal.records_per_sample` (§8.3, now documented, and no longer dropped on load by Python and Rust), else 1. `flatten` keeps the field as written on the flattened parameter's `update.from`.
- **`records_per_sample_invalid`**, a new diagnostic. A document is refused when a non-`data` rule carries the field, when an effective 2 reads a source with no `temporal` block or with a `temporal` block that has no `start` (such a source is time-invariant), or when an effective 2 meets a record shape whose first dimension does not have exactly two members. The check covers parameters in subsystems at any depth, and reports the rule's own pointer (`/update`, or `/update/<i>` for an array of rules). The record shape is the declared `shape` whenever one is declared, `[]` included; a parameter with no `shape` takes its record shape from every `param_to_var` target it is mapped onto, and each one is checked. Validation checks the record shapes it can see; a target that arrives through a `coupling_import`, or sits in a file mounted by `ref` that validation has not yet mounted, is checked by `flatten`, which refuses it with the same code. `tests/conformance/records_per_sample/` pins all of this in the five bindings.
- **A `data`-fed parameter may omit `shape`** (`esm-schema.json`). `schedule` and `remesh` parameters still require one. A shapeless data-fed parameter takes the shape of the shaped target it is `param_to_var`-mapped onto (above), and is otherwise a scalar. This is how a data component declares a field once and each consumer gives it the record axis and its own grid. An explicit `"shape": []` still declares a scalar.
- **`providers_from_document` builds every provider with EarthSciIO's constructor** (Python `source_from_esm`, Julia `provider_from_esm`, Rust `DataSource::from_esm`), so all three read a source the same way:
  - **Dated URLs and mirrors.** A `url_template` such as `{date:%Y%m%d}` is expanded for each record, and `mirrors` are tried when the primary location is missing. Both used to be ignored.
  - **Calendar cadences.** A `P1M` source steps by calendar months; Rust and Python used to step 30.436875 days. Julia used to build const providers only.
  - **New options:** `substitutions`, per source, binds the custom placeholders a mount's `url_substitutions` left unbound; `window` is the run's start and end in UTC (with none, `solver.time_span` supplies one); and `records_per_sample`, per consuming parameter, may restate the document's effective value but not change it. In Rust these come through `providers_from_document_with(doc, cache_root, &DocumentProviderOptions { .. })`; the old `providers_from_document` signature still works.
  - **`records_per_sample`.** Each consuming parameter's provider gets that parameter's effective value, so two parameters reading one source may differ.
  - **Selections on a time-varying source** are applied after the record is read, never pushed down to the reader, and such a provider reports `supports_selection = false`. A record table (`codes` / `record_filter`) on a time-varying source is decoded again at each new record. With `records_per_sample = 2`, a declared `select` skips the leading two-record axis, and a record table is refused.
  - An empty `url_overrides` entry is refused in all three bindings.
  - TypeScript and Go have no `providers_from_document`.
- **`forcing_from_sample`** (Julia, Rust; API_SPEC §5.8, "Forcing sets") is the check and conversion `esm_problem` applies to a provider sample, so a runtime that builds its own forcing sets for `rhs_program` gets the Problem's buffers bit for bit.
  - **Julia** (exported): `forcing_from_sample(sample, slot::ForcingSlot) -> Vector{Float64}` and `forcing_from_sample(sample, name; shape = nothing) -> Array{Float64}`.
  - **Rust** (crate root): `forcing_from_sample(&HashMap<String, NativeField>, &ForcingSlot) -> Result<Arc<[f64]>, ProviderError>`.
  - A declared `unit_conversion` is not applied, because `providers_from_document`'s providers already apply it.
- **A top-level `reaction_systems.<k>` `{ref}` mounts in every binding** (esm-spec §4.7, "Two mount forms, one mechanism"). It is the reaction-system twin of a top-level `models.<k>` `{ref}`, and goes through the same mount pipeline: nested mounts, the library and version gates, the edge's `bindings`, `index_set_rename` and the `index_sets` merge, the `data_sources` hoist and the element-type check.
  - **Rust** used to refuse it with `mount_form_unsupported`. **Julia** mounted it, but ignored the edge's `bindings`, dropped the leaf's `index_sets` and refused `index_set_rename`.
  - The selector (`model` / `reaction_system`) applies at both forms. A leaf with no component of the form's kind, a leaf with several and no selector, and a selector naming a component the leaf does not declare are each `unresolved_subsystem_ref` at `/<block>/<k>` in every binding. At `models.<k>` this changes three bindings: Python used to ignore the `model` selector and take the first model; TypeScript and Go refused a selected multi-model leaf as `ambiguous_subsystem_ref`; Rust raised `toplevel_model_ref_unresolved`.
  - A leaf with one model and one reaction system, mounted at `models.<k>`, mounts its model in every binding. TypeScript and Go used to refuse it.
  - No binding raises `mount_form_unsupported` or `subsystem_index_set_rename_unsupported_mount_form` any more.
- **`metadata.esio_format`** on a data source (esm-spec §8.1.1) names the reader format `providers_from_document` uses. It is optional, and load, validation and flatten ignore it.

## Dependencies

- **EarthSciIO 0.3.0** is now the minimum for the data bridge. It is the first release with the per-source constructors above.
  - **Julia:** the EarthSciIO extension's compat is `"0.3"` (was `"0.1.4, 0.2"`).
  - **Rust:** the `esio` feature depends on `earthsciio` 0.3.0 from crates.io.
  - **Python:** the bridge stays opt-in and imports `earthsciio` lazily, with no pinned version; `providers_from_document` needs 0.3.0.
  - With 0.3.0, a placeholder in a `url_template` that nothing binds is refused by EarthSciIO with the code `esm_template_unbound`. In Julia that is an `EarthSciIO.EsmSourceError` (EarthSciIO 0.2 raised `EsmTemplateError`).
- **Julia:** a new package extension, `EarthSciASTSolverWorkloadExt`, loads with SciMLBase and OrdinaryDiffEqTsit5 and precompiles `solve` and `run_inline_tests`.

## Other changes

- **Julia: faster first `esm_problem` after the solvers load.** Loading the solver stack used to discard much of EarthSciAST's precompiled build path, so the first build after it recompiled. Most of that is gone, and with the new extension the first `solve` and `run_inline_tests` are precompiled too. Environments that also load ForwardDiff or OrdinaryDiffEqRosenbrock gain less.
- **Julia: schema validation is linear in expression size.** Loading a document with a large, deeply nested expression spent nearly all its time in JSON-schema validation, at a cost per node that grew with its depth. `validate_schema` now walks a compiled copy of the schema, and reports the same errors at the same paths as before.
- **Julia: a 0-d data-fed parameter reads its data.** A scalar parameter whose value comes from a provider, or from a one-cell `const_arrays` / `param_arrays` entry, gets no `p` slot: the right-hand side reads the data, and `parameter_classes` reports it as `:forcing` or `:const_folded`. The Problem used to read the declared default.
- **Rust: discrete providers are sampled at construction.** `esm_problem` samples every discrete provider at `sample_time` (default `tspan[0]`), so the Problem and `rhs_program`'s default forcing set hold the record in effect there instead of the declared default. Every solve, including one of a `remake`, starts from the record in effect at its start, and refreshes at every refresh time inside the span, with or without `saveat`. A provider keyed by a parameter's full name (`M.s`) on a one-model document now feeds it; it used to write its data where the model never read it.
- **Rust: a data-fed parameter with an inline array `default` is a forcing slot.** It used to be baked into the program as a constant, which also hid a provider's data behind it. A parameter that recomputes itself from an `expression` and has an array default is now refused as an unsupported discrete parameter, instead of being frozen at its default.
- **Rust: a file variable for `records_per_sample = 2` must store time first.** A variable stored as `(row, time)` is refused with an error naming it; Python and Julia accept either order.
- **Python: `Pre(x)` on a right-hand side evaluates as `x`** (esm-spec §5.1), as in Julia and Rust. The `interpreter`, `native` and `sympy` compilers used to refuse it as `unevaluable_operator` or an unsupported operation. The public `to_sympy` still keeps `Pre` as an opaque function.
- **Python: a mounted component's events reach the flattened system** at both top-level mount forms.
- **Go: an unresolved top-level mount no longer loads as an empty model or reaction system.** `Flatten`, `Validate` and `DeriveODEs` fail with `unresolved_subsystem_ref`.
