A breaking release for Rust and TypeScript code that builds a flattened system's loader fields, and for Rust code that matches every `FlattenError` variant. The `.esm` format stays at **esm 1.3.0**. Every document that loaded under 0.8.0 loads unchanged unless it asks a data source for two records per sample in a way the source or the parameter's shape cannot deliver (§8.5.1, below).

## Breaking changes

- **`LoaderField` gains the effective `records_per_sample`** (esm-libraries-spec §4.7.5, "Loader fields"). Every binding's loader-field entry now says whether the field holds one record or the pair that brackets the query time.
  - **Rust:** `LoaderField` has a new public field `records_per_sample: u8`. Code that builds the struct literally must set it. Deserializing an older serialized `LoaderField` still works: the field defaults to 1.
  - **TypeScript:** `LoaderField.recordsPerSample` is a new required field. Code that builds a `LoaderField` object must set it.
  - Julia (`records_per_sample`, a keyword argument defaulting to 1), Python (`records_per_sample`) and Go (`RecordsPerSample`) add the field without breaking existing callers.
- **Rust: `FlattenError::RecordsPerSample(DiagnosticError)`** is a new variant, raised when `flatten` refuses a record shape with `records_per_sample_invalid` (below). A `match` on `FlattenError` with no wildcard arm must handle it.

## New

- **`from.records_per_sample` on a `data` rule** (esm-spec §8.5.1). `1` delivers the record at or before the query time; `2` delivers that record and the next one, stacked along the parameter's first declared dimension, which must be an index set of exactly two members. The source does not interpolate; the model blends the pair itself. The effective value is the rule's own field, else the source's `temporal.records_per_sample` (§8.3, now documented, and no longer dropped on load by Python and Rust), else 1. `flatten` keeps the field as written on the flattened parameter's `update.from`.
- **`records_per_sample_invalid`**, a new diagnostic. A document is refused when a non-`data` rule carries the field, when an effective 2 reads a source with no `temporal` block, or when an effective 2 meets a record shape whose first dimension does not have exactly two members. The check covers parameters in subsystems at any depth, and reports the rule's own pointer (`/update`, or `/update/<i>` for an array of rules). A parameter declared with an empty shape takes its record shape from every `param_to_var` target it is mapped onto, and each one is checked. Validation checks the record shapes it can see; a target that arrives through a `coupling_import`, or sits in a file mounted by `ref` that validation has not yet mounted, is checked by `flatten`, which refuses it with the same code.
- **`metadata.esio_format`** on a data source (esm-spec §8.1.1) names the reader format `providers_from_document` uses. It is optional, and load, validation and flatten ignore it.

`tests/conformance/records_per_sample/` pins all of this in the five bindings.
