A breaking release, for two reasons. EarthSciAST now requires **EarthSciIO 0.4**, which refuses a run window that its data does not cover. In Rust, `ModelVariable` gains two public fields. The `.esm` format moves to **esm 2.1.0**, which only adds features: optional `lb` / `ub` bounds on a model variable. Every esm 2.0.0 document loads, flattens and runs as before. The unit registry gains `ng`, `mN` and `dyn`, and the Rust native compiler accepts one more `makearray` shape that it used to refuse.

## Breaking changes

- **EarthSciIO 0.4 is required** (Julia `EarthSciIO = "0.4"`, was `"0.3"`; Rust's `esio` feature now depends on `earthsciio` 0.4.0. Python declares no EarthSciIO dependency). This EarthSciIO release has one breaking change. A run window that starts before a source's `start`, ends after its `end`, or is empty is now refused with `esm_window_uncovered`. Before, it was clamped to the data. A run that relied on that clamping must now ask for a window inside the source's data.
- **Rust: `ModelVariable` has two new public fields**, `lb` and `ub`, both `Option<VariableBound>` (below). A struct literal that does not end in `..Default::default()` must set them.
- **Rust: `migrate()` relabels a 1.x document as the current version**, now 2.1.0, instead of always 2.0.0. The other four bindings already did this.

## New

- **Variable bounds `lb` / `ub`** (esm-spec §6.3.2, new, and the §4.9.5 table; esm-libraries-spec §4.7.5; MIGRATION.md, "esm 2.1.0"). A model variable may have an optional lower bound and an optional upper bound. Each one is either a number in the variable's `units`, or a reference to another variable, parameter or observed. A reference is written and resolved exactly like a variable reference in the model's expressions:

  ```json
  "theta":  {"type": "parameter", "units": "1", "default": 0.5, "lb": 0, "ub": 1},
  "E_NaCl": {"type": "unknown", "units": "mol/m^3", "lb": 0, "ub": "E_NaCl_max"},
  "W":      {"type": "unknown", "units": "kg/m^3", "ub": "Ions.cap"}
  ```

  A bound states a physical fact about the variable. The spec does not say how a solver should use it. The first consumer is EarthSciIntegrator's bound-constrained algebraic solves.
  - **Format version.** The schema `$id` and `SCHEMA_VERSION` move to 2.1.0 in every binding. A document that carries bounds must declare `esm` 2.1.0 or later. A flattened document that carries bounds is written as esm 2.1.0.
  - **Validation** checks bounds in all five bindings, and holds each mounted file to its own declared version. The new diagnostics are:
    - `variable_bounds_version_too_old`: a bound in a document that declares esm below 2.1.0.
    - `variable_bound_shape_mismatch`: a referenced bound that is neither a scalar nor the same shape as the variable it bounds.
    - `variable_bound_circular`: a variable bounded by itself, or by an observed that depends on it, directly or through other observeds.
    - `variable_bounds_inverted`: a numeric `lb` larger than a numeric `ub`.
    - A reference that does not resolve is the existing `undefined_variable`.
  - **Flattening** namespaces a referenced bound. Bounds follow `operator_compose` renames and `variable_map` substitution, and a `variable_map` with a scale factor turns a referenced bound into `factor * source`. Corpus cases: `variable_bounds` and `variable_bounds_coupled`.
  - **Code:** Rust and Go add `VariableBound`. Rust's is an enum (`Number`, `Reference`, and `Expression`, which only flattening produces). Go adds `ModelVariable.LB` / `UB` and the `CodeVariableBound…` constants. Julia, Python and TypeScript parse, write, validate and flatten bounds in their existing document types. `api-surface.json` and API_SPEC.md §6 are regenerated.
- **Units `ng`, `mN` and `dyn`** (esm-spec §4.8.1; issue #710). Since esm 2.0.0 the unit table has no SI-prefix mechanism, so `ng/m^3` and `mN/m` stopped resolving. These are the usual units for aerosol mass concentrations and emission factors, and for surface tension. `ng` is exactly 1e-12 kg, `mN` is exactly 1e-3 N, and `dyn`, the CGS unit of force beside `erg`, is exactly 1e-5 N. They are added to all five bindings and the Lean model. The unit-registry golden pins `ng/m^3`, `dyn/cm` and `mN/m` with exact scales. It also pins `pg`, `kN` and `kdyn` as rejected, so a binding cannot pass by resolving the new units through a units library's prefix rules.

## Other changes

- **Rust native: an `index` into a `makearray` of lower rank than the enclosing box** is now compiled (issue #709). This is the natural way to write a per-cell array, for example `index(makearray(…; values a[k], b[k]), i)` inside a `faq` over `(k, i)`. The native compiler used to refuse it with "makearray: region rank != output box rank", while the interpreter evaluated it. The supported cases are subscripts that shift one box axis each by a unit step or are constants, and that stay inside the makearray's bounds. Later regions overwrite earlier ones, and uncovered cells stay zero, as in the interpreter. Results match the interpreter bit for bit. The EqWeFiC MOSAIC documents from the issue now run under the default compiler.
- **Formal model: groundwork for Markdown and Typst source formats.** The Lean model now holds the document-format notation as data: operators with their LaTeX and Typst forms, precedence, name shapes, reaction layout and accepted input spellings. It also holds JSON, YAML and Typst block codecs with proven round trips, the canonical number spelling (CONFORMANCE_SPEC §5.5.3.1), and a canonical unit spelling with proofs that it is idempotent and keeps the unit's dimension and scale. No binding changes yet.
- **Julia CI:** the threaded-regrid test no longer builds the N = 1000 regrid fixture under the interpreter. Since esm 2.0.0 that build sweeps all 10^6 polygon pairs, which pushed the `julia-tests` legs to their time limits. Native and interpreter agreement on that fixture is still tested at N = 100.
