A breaking release: the expression tree a reaction system lowers to changed shape in four bindings (#572). The `.esm` format stays at **esm 1.3.0**, and every document that loaded under 0.5.0 loads unchanged. Lowered equations evaluate to the same numbers as before; what changed is the tree, which esm-libraries-spec §4.6.2 now fixes exactly so that every binding writes the same bytes.

## Breaking changes

- **The tree `derive_odes` and `flatten` build for a reaction system** (#572). Every binding now emits the §4.6.2 form, pinned by `tests/conformance/reactions/lowering_form.json`. The rate law is one n-ary `*` with the rate first (`k * A * B`), each species' term is the bare rate law for a net coefficient of 1 and `c * rate` otherwise, with `c` an integer literal when it is integral, and several terms form one n-ary `+`. A loss of 1 is `-1 * rate`. Code that pattern-matches lowered equations, or compares them to stored trees or strings, needs updating:
  - **Python, Go and TypeScript `flatten`:** products and sums are no longer nested two operands at a time, and a literal `1` rate is kept (`1 * A`, not `A`).
  - **Rust:** integral coefficients are `Expr::Integer`, not `Expr::Number` (`Expr::Integer(-1)` where 0.5.0 had `Expr::Number(-1.0)`).
  - **Julia and TypeScript `deriveOdes`:** a loss of 1 is `-1 * rate`, not a unary minus. Julia writes integral coefficients as integer literals (`-2`, not `-2.0`).
  - **A species listed more than once on one side of a reaction** gets one rate-law factor per entry (`A + A` gives `k * A * A` and coefficient `-2`). Python used to keep only the last entry for that species.
  - An integral coefficient or exponent is an integer literal only when it is representable in Int64; larger values stay floats in every binding.
- **TypeScript `deriveOdes`** (#572) no longer emits `D(X, t) = 0` for a species no reaction changes; such a species gets no equation, as esm-libraries-spec §4.6.1 requires and the other bindings already did. It also now throws an `EsmDiagnosticError` with code `undefined_species` for a substrate or product the system does not declare, where it used to drop it silently.

## Other changes

- **Python `Reaction`** gains `substrate_entries` and `product_entries`, the entries in listed order with repeats kept (#572). The `reactants` / `products` maps now sum a repeated species' coefficients instead of keeping the last one.
- **Julia accepts SciMLBase 3** alongside SciMLBase 2 (#571), and the OrdinaryDiffEq solver packages at 2.x. ModelingToolkitBase is held at `1 - 1.42`, because the ModelingToolkit extension does not yet work with later releases. Callers of `EnsembleProblem(prob, rewrite)` must write `rewrite` for the SciMLBase they load: `(prob, i, repeat)` under 2, `(prob, ctx)` under 3.
- **Julia works with JSONSchema.jl 1.6** (#572), which changed an internal function EarthSciAST's schema validator calls. Under 0.5.0, an environment that resolves JSONSchema 1.6 fails to precompile EarthSciAST.
- **Spec fixes** (#570): `min` and `max` propagate NaN in every argument position (esm-spec §4.2, §4.9.5; CONFORMANCE_SPEC §5.23). Rust still drops NaN there, tracked in #568. searchsorted tables are "non-decreasing" (§9.2). Several CONFORMANCE_SPEC sections were renumbered: the second §5.45 is now §5.52.
- **A Lean model of the spec** has started under `formal/` (#570), with an inventory of every `MUST` clause and an audit gate. It does not affect any binding.
