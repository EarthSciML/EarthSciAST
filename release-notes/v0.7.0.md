A breaking release: the units checker and the load-time checks are stricter, one error code is renamed, and the minimum Go, Python and Node versions go up. The `.esm` format stays at **esm 1.3.0**. Most documents that loaded under 0.6.0 still load unchanged (every file under `tests/valid`, `lib/` and `tests/conformance` does), but some no longer load. These are documents with a unit error that some bindings used to miss, a broken function table the document never looks up, a unit string that breaks the §4.8.2 grammar, or a newer file that mounts an older one using a construct the older version lacks. The breaking changes below list each case. Many more documents now load with a new warning, `units_dimensionless_literal_mismatch`, which warns about a rule the next major esm version will enforce. One addition to the 1.3.0 schema, `url_substitutions` on a mount edge (#618), arrives without a version bump, so a document that uses it does not load under 0.6.0.

## Breaking changes

- **New unit warnings on documents that are still valid** (#575). A bare numeric literal (or a `const` with no `units`) will become dimensionless in the next major esm version. Today it takes on its neighbours' unit. Every binding now types each equation, initialization equation, constraint and reaction rate under both rules, and where only the new rule finds a mismatch it adds `units_dimensionless_literal_mismatch` to `unit_warnings`. Each warning comes with the JSON pointer and the `const(…, units "…")` repair. `T - 273.15` with `T` in K is one example. Zero in any spelling stays neutral. Errors and `is_valid` do not change, and a failure inside the warning pass becomes one warning, never an error. `scripts/codemod-dimensionless-literals.py` proposes the repairs (#586).
- **Two unit-checker fixes make some documents invalid with no warning first** (#575). Both bring the bindings into line with the spec and with each other:
  - **`ic(x)` carries `x`'s unit** in Go, TypeScript and Julia, as it already did in Python and Rust. `ic(T [K]) = p0 [Pa]` is now a `unit_inconsistency` everywhere.
  - **An undeclared `t` is in seconds** in Go, TypeScript, Julia and Python, as it already was in Rust (§4.9.1). A model that leaves `t` undeclared and writes `sin(t)` or `exp(-t)` is now an error.
  - Also: the "no time unit can reconcile the two sides" derivative check now counts toward a site's verdict, and Julia types a template-invocation rate through its expansion.
- **Version gates read each file's own `esm`** (#584, esm-spec §4.7). Go, Julia and Rust used to apply the gates to the resolved document, judged against the root's version. Now:
  - A file that declares 1.1.0 or 1.2.0 and mounts a 1.0.0 file is rejected if that 1.0.0 file carries a unit-bearing `const` (`const_units_version_too_old`) or a top-level `solver` block (`solver_version_too_old`). Go, Julia and Rust used to accept this.
  - In Go, a 1.0.0 root that uses `faq` no longer escapes `faq_version_too_old` by mounting something.
  - The other direction now loads: a 1.0.0 file may mount a 1.2.0 file that uses unit-bearing `const`.
  - Every gate except `faq_version_too_old` reads the declared version as raised by the `aggregate` normalization (the 1.1.0 floor). The `solver.external` and `solver.time_span` gates still apply to the root only.
- **Julia's angle checks match the other bindings** (#584). `rad` against `sr`, and `m*rad` against `m`, are now unit mismatches in Julia. Julia used to accept them.
- **Function-table and closed-function checks run at load, on every table** (#585, esm-spec §9.2, §9.5.5). All five bindings used to raise these at build or evaluation time, and only for tables a lookup used. Now `validate()` and load reject a broken table even when nothing looks it up, with the ten table checks in one pinned order. New codes: `table_axis_too_short`, `table_axis_duplicate_name`, `table_axis_non_monotonic`, `table_data_nan`, `table_outputs_duplicate_name`, `table_outputs_length_mismatch`, `table_lookup_args_nonempty` (a `table_lookup` with a non-empty `args`), `interp_axis_not_const`, `interp_table_not_const` and `enum_duplicate_value` (TypeScript and Go used to accept duplicate enum values silently).
- **The error code `searchsorted_nan_in_table` is now `searchsorted_nan`** in all five bindings (#585). The registry constants are renamed to match: `SEARCHSORTED_NAN` in Julia, Python, Rust and TypeScript, and `CodeSearchsortedNaN` in Go. Each binding used to give a `searchsorted` table that is not a `const` array a different code. Every binding now raises `interp_axis_not_const`, checked before NaN and monotonicity.
- **The unit-string grammar is strict in every binding** (#585, esm-spec §4.8.2). Strings that some bindings accepted are now rejected:
  - a whitespace-only string (only `""` is dimensionless);
  - a `+` sign on an exponent (`m^+2`), a parenthesized or chained exponent (`m^(-2)`, `m^2^3`), or `m^1e3`;
  - `01` or `1.0` in place of the atom `1`;
  - a run of letters and digits that is not a registered symbol, such as `s1`, `kgm` or `cm3`;
  - a lone `°` (Python).

  Rust's SI-prefix fallback for symbols missing from the registry is gone, and TypeScript and Julia now read `%h` as `%` times `h`.
- **Some `datetime.*`, `table_lookup` and `interp` results change** (#585):
  - **`datetime.*`:** fractional times floor toward −∞ in every binding. Python used to round to the microsecond and failed outside years 1–9999, Go rounded to the nanosecond, Julia truncated toward zero, and TypeScript got every date before year 0 wrong. Rust no longer reports hour 24 or wraps an Int32 year.
  - **Overflow:** a NaN or infinite time, or a year outside Int32, raises `closed_function_overflow` from every `datetime.*` function.
  - **`julian_day`:** now the standard Julian Date everywhere. This changes results only before −4800-03-01.
  - **`nearest` table lookups:** they now return the true nearest knot, with ties going to the lower knot and the ends clamped. The old lowering was wrong in every binding.
  - **`table_lookup` outputs:** an omitted `output` means 0, and a single-output table lowers with its whole `data`.
- **NaN propagates through `max` and `min` reductions in Python and Rust** (#615), as esm-spec §4.2 requires and Julia already did. Python used to let the first term seed the fold, and Rust skipped NaN, including in its elementwise `max`/`min`.
- **Higher minimum toolchains** (#599):
  - **Go:** `go.mod` declares `go 1.26`. `go-playground/validator` and all `golang.org/x/*` modules are no longer dependencies.
  - **Python:** `earthsci-ast` requires Python 3.11 or later.
  - **TypeScript:** the package needs Node 22 or later.
- **Rust `ProblemOptions` has a new public field, `retain_data_fields`** (#617). Code that builds `ProblemOptions` as a struct literal without `..Default::default()` must add it.

## Other changes

- **Mount-edge `url_substitutions`** (#618, esm-spec §4.7), in all five bindings. A `{ref}` mount edge can now bind the bare `{name}` placeholders in the referenced document's `data_sources` locations, so many run documents can mount one shared data catalogue, each pointing it at its own data directory. A key that names no placeholder is `url_substitution_unknown_name`. A value that is not a string, or that contains `{`, `}`, `?` or `#`, is `data_source_url_unresolved`. Related changes in the same PR:
  - **A mounted document's `data_sources` now merge into the mounting document at both mount forms in every binding.** Before, Python, TypeScript and Go never merged them, Rust merged only at the top-level `models.<k>` form, and Julia merged only on its native walk. The mounting document's own entry wins a name clash. If two mounts contribute the same source name with different entries, loading fails with the new code `data_source_merge_conflict`.
  - **An edge's `bindings` reach through an assembly** to a metaparameter that only a document further down the mount tree declares. This used to be `template_import_unknown_name`.
  - **A relative location in a document loaded from a URL** joins onto that URL's directory by RFC 3986 in every binding. Python and TypeScript used to produce a meaningless `file://` path.
  - **Julia:** a mounted file's relative `data_sources` resolve against that file's directory, not the root's. Two sibling edges that mount the same file are no longer reported as a circular reference. `resolve_subsystem_refs!` returns the resolved `EsmFile`, which carries the merged sources when the root declared none; use the return value.
- **Rust builds an ingesting document that holds several models** (#616). A document with a `kind: "data"` parameter, or a caller passing `build_providers` or `const_arrays`, used to fail with "document holds several models; pass model_name" when it held more than one model. With no `model_name`, the whole document now builds as one dot-namespaced system, as the non-ingesting routes and the Python and Julia `esm_problem` already did, and `esm test` passes on such documents. In such a build, a bare override, provider or `const_arrays` key that matches parameters in more than one model is an error that lists the full names to use. A gated provider for a parameter inside a mounted subsystem now binds under `Leaf.sr`; it used to bind under `sr`, where nothing read it. An explicit `model_name` (`esm simulate --model`) still builds that model alone.
- **Rust: a data-fed parameter can be asserted and observed** like a computed variable (#617). Inline tests and `esm simulate --observed` can name one, and `observed_field` returns its ingested values when `ProblemOptions::retain_data_fields` names it. A fix in the same PR: in a document with differential equations, the right-hand side used to read such a parameter's `default` (often 0) instead of the ingested data.
- **Rust: a data-fed or precision-declaring leaf mounted as a subsystem builds** (#612). A subsystem's data-fed parameters used to be unbound (`E_TREEWALK_UNBOUND_NAME`), and a subsystem variable's `element_type` was refused as `element_type_uncarried`.
- **Rust `initial_state(prob)`** (#602) returns the state a Problem integrates from, one value per element of `state_variable_names()`, after `u0` overrides, initialization equations, `ic` equations, field initial conditions and defaults are applied. It does not integrate.
- **`time_origin` and `timestamp_to_seconds`** in Julia, Python and Rust (#587, #600) expose the §2.2.7 clock arithmetic that `resolve_time_span` uses. Each takes a document or its `domain`, typed or raw JSON. Rust adds the `TimeOriginSource` trait for this. They raise `timestamp_malformed`, `timestamp_no_calendar_day` or `time_origin_invalid`. `resolve_time_span` still raises `solver_time_span_invalid`.
- **An angle meeting a pure number counts as dimensionless** (#584, esm-spec §4.8.3). This applies in `+`, `-`, `min`, `max`, `ifelse` branches, comparisons, equation sides, observed declarations and the arguments of `exp`, `log` and similar functions. So `π/2 - 2*atan(x)` checks without a `1/rad` on the `2`. `deg` against a plain number is still a scale mismatch.
- **`MJ` (megajoule)** is in the unit registry (#601).
- **Flatten: a loop symbol shadows a same-named variable** (#610, esm-spec §4.3). Julia used to namespace an `faq` index that shares a name with one of the model's variables as if it were that variable (`M.u[M.j]`), which silently changed the model. The rule now covers every node that binds a name, including `integral`'s `int_var`, in all bindings. A dotted reference such as `j.x` is never shadowed. TypeScript and Go used to apply it to `faq` only, and Python to `faq`, `argmin` and `argmax`.
- **Julia native compiler fixes** (#609). In a lifted equation, the native compiler sometimes evaluated a `makearray` region other than the one each cell selects, giving wrong values with no error. That is fixed, and a contracting `faq` inside such a region no longer raises `compiler_refused_rule`.
- **Equality-filtered `faq` runs in one pass** under the Julia and Rust native compilers (#615). A `filter` that pins an output index (`j == e`) used to cost time proportional to the square of the box size. In the same PR, a ragged range whose parent index is contracted now evaluates correctly: the Rust interpreter used to give 0, and Julia and Python refused it. Python also accepts a filter over a ragged range.
- **The Rust library builds without the `solve` feature** (#608). **The `esm` binaries attached to GitHub releases include the EarthSciIO readers**, so a downloaded `esm` reads parquet, netcdf and zarr sources.
- **Smaller fixes from the security sweep** (#599): Go quotes document-supplied names safely in diagnostics, and a unit exponent too large for Int32 is now a parse error instead of wrapping. TypeScript `latexName` escapes fully, and its regular expressions run in linear time. Rust validation messages from the jsonschema 0.60 port read slightly differently; codes and paths are unchanged.
- **Julia accepts Catalyst 17, DomainSets 0.8 and EarthSciIO 0.2** (#590, #603, #611). The Rust crate's optional `esio` and `xla` features now take earthsciio 0.2 and xla 0.5.4 or later.
- **`lib/solar.esm` declares esm 1.2.0** and carries unit-bearing `const`s (#586). A 1.0.0 document can still mount it under the per-file version gates.
- **Spec and formal model** (#585): the Lean model now covers the closed functions and the unit registry. Several false claims in the spec are corrected. Bounds for fused multiply-add (FMA) evaluation of `interp.linear` (2 ulp) and `interp.bilinear` (17/2 ulp) are now stated in place of the old relative tolerance.
- **Release, docs and CI infrastructure** (#577, #578, #579, #583, #589, #594, #598, #611): shared EarthSciML release and lint workflows, the docs site moved to earthsci.dev with versioned docs, Dependabot in place of the custom security scan, and Runic formatting of the Julia sources. None of this changes the packages.
