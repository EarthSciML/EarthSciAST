A breaking release. The `.esm` format moves to **esm 2.0.0**: every external function leaves the expression AST. The `fn` op (every `datetime.*` and `interp.*` name), the `function_tables` block and `table_lookup`, `skolem`, `rank`, `argmin`, `argmax`, `intersect_polygon`, `polygon_intersection_area` (with its `manifold` field) and the `aggregate` spelling of `faq` are removed; a document that uses any of them, whatever `esm` it declares, is refused at load with `removed_op`. Each has a standard-library template replacement except `intersect_polygon`; the codemod `python -m earthsci_ast.migrate FILE...` rewrites a 1.x document, and `MIGRATION.md` ("esm 2.0.0") lists every replacement. A 1.x document (1.0.0–1.3.0) that uses none of them still loads unchanged. In code, the release breaks every binding's closed-function, function-table, geometry and relational helpers, which are deleted (below); Rust code that builds an `IndexSet`, `ProblemOptions`, `FlattenMetadata` or `ExpressionNode` literal without the new fields, or that reads `function_tables` or the removed expression-node fields; Julia code that loads the GeometryOps extension; and Python installs that ask for the `geometry` extra. Other documents that loaded or built under 0.10.0 are now refused: one that writes `records_per_sample: 2` over a plain size-2 first axis, a `faq` that reads a shaped variable by bare name (`faq_bare_array_operand`), a coupling entry of `type: "event"` at build, an `ic` that reads a state at construction, and in Julia a scalar parameter fed more than one value. Several are now accepted: a template applied over an array argument, a recurrence group of several variables along one axis, an `ic` that reads `t` or data, and an index set marked `"records": true`.

## Breaking changes

- **esm 2.0.0: the external functions are removed** (esm-spec §4.2, "Removed ops"; §4.4, §9.1, §9.2, §9.4 and §9.5 are now "(Removed at 2.0.0)" stubs, so section numbers elsewhere do not move). In 0.10.0 each of these had a pure-AST template beside it; 0.11.0 deletes the built-in forms from the spec, the schema, all five bindings and the Lean model.
  - **Removed and replaced:** `fn` with `datetime.*` → the templates of the same names in `esm:std/calendar.esm`; `fn` with `interp.*` → `searchsorted`, `linear` and `bilinear` in `esm:std/interp.esm`, each axis length now an explicit parameter; `function_tables` and `table_lookup` → the table's data and axes as `const` arrays read by `linear` / `bilinear`; `skolem` → `pair_key` / `edge_key` in `esm:std/relational.esm`, or one integer column per component on a `join.on` key; `rank` → the member's loop index over the `distinct` set, or `rank_of` / `rank_of_set`; `argmin` / `argmax` → the templates of the same names, or `argmin_where` / `argmax_where`; `polygon_intersection_area` → `overlap_area_planar`, or `overlap_area_spherical` over a `lonlat_to_unit` stack, in `esm:std/geometry.esm`; `aggregate` → `faq`. `intersect_polygon` has no replacement. `distinct` and `join` stay.
  - **Loading.** A removed op or a `function_tables` block anywhere in a document is the hard error `removed_op`, raised by name before the version gates and schema validation, naming the op or field and its node path and pointing at the codemod. No binding rewrites a document at load. Fixtures: `tests/invalid/removed_ops/`.
  - **1.x documents.** A document declaring 1.0.0 through 1.3.0 that uses no removed op loads, on its own and when mounted or imported into a 2.0.0 document, and its own 1.x version gates (`faq_version_too_old`, the `solver_*` and `const_units` gates) still apply. Major versions 0 and 3 or above are refused with "Unsupported major version N. This library supports major versions 1, 2." (`tests/version_compatibility/compatibility_matrix.json`); a newer minor within major 1 or 2 loads with a warning. Go still has no major-version gate. `SCHEMA_VERSION` is `2.0.0` in every binding, and the schema's `$id` is `.../esm/2.0.0/...`.
  - **`migrate()` / `can_migrate()`** in every binding relabel a 1.x document as 2.0.0 when it uses no removed op, and refuse with `removed_op` otherwise.
  - **The codemod** is in Python only: `python -m earthsci_ast.migrate FILE... [-o OUT] [--check] [--key-bounds ...]`, or `earthsci_ast.migration.migrate_document(doc)`. It replaces each removed node with its template call, adds the `expression_template_imports` entry, moves `function_tables` data inline and sets `esm` to 2.0.0. `rank(S)` becomes the loop index minus one (the op's 0-based values) and a two-component `skolem` key becomes a directed `pair_key`, whose component ranges `--key-bounds` supplies. It refuses `intersect_polygon`, an `fn` outside `datetime.*` / `interp.*`, a table with `out_of_bounds: "error"`, and `skolem` / `rank` shapes it cannot map.
  - **What changes numerically.** The calendar, interpolation, table and key templates reproduce the removed ops' binary64 results bit for bit. Overlap areas agree with the old geometry backends within the CONFORMANCE_SPEC §5.8.2 tolerance, not bit for bit; a `geodesic` document becomes `overlap_area_spherical`, the great-circle model the backends used. The `argmin` / `argmax` templates let a NaN candidate win at its first occurrence, where the op skipped a NaN after the first candidate. The calendar templates return NaN for `|t| ≥ 2^52` s, where `datetime.*` answered or raised `closed_function_overflow`. Under `element_type: "Float32"` a template is an ordinary expression and is not refused; calendar fields of a present-day time lose precision there.
  - **New esm-spec §9.8, "Standard-library contracts"**, makes normative what each template computes: search and interpolation (§9.8.1), calendar fields (§9.8.2), arg-witnesses, keys and ranks (§9.8.3), and overlap areas (§9.8.4).
  - **Diagnostics that only the removed ops could raise are gone:** `unknown_closed_function`, `closed_function_*`, `interp_*`, `searchsorted_*`, `table_*`, `table_lookup_*` and `geometry_manifold_invalid`.
- **The removed ops' code surfaces are deleted** in every binding (`api-surface.json` is regenerated).
  - **Rust:** `closed_function_names`, `evaluate_closed_function`, `ClosedArg`, `ClosedValue`, `ClosedFunctionError`; the geometry module (`intersect_polygon`, `polygon_area`, `shoelace_area`, `shoelace_signed_area`, `area_tolerance_ok`, `sliver_atol`, `SLIVER_ATOL_FACTOR`, `GeometryError`, `Manifold`); the relational helpers `skolem`, `skolem_edge`, `rank`, `rank_with_base` and `Ranking`; `FunctionTable`, `FunctionTableAxis`, and the `function_tables` fields of `EsmFile` and `FlattenedSystem`. `ExpressionNode` loses the fields `table`, `axes`, `output`, `manifold`, `label` and `arg`.
  - **Julia:** `closed_function_names`, `evaluate_closed_function`, `evaluate_closed_function_ad`, `ClosedFunctionError`, `FunctionTable`, `FunctionTableAxis` and `build_spatial_index`. The GeometryOps package extension is gone, with its weak dependencies.
  - **Python:** `FunctionTable`, `FunctionTableAxis`, `skolem`, `skolem_edge`, `rank`, `Ranking`, `intersect_polygon`, `polygon_area`, `polygon_area_via_faq`, `area_tolerance_ok`, `densify_parallel_edges`, `MANIFOLDS`, `GeometryError` and `GeometryBackendUnavailable`, and the `geometry` install extra (`spherely`).
  - **TypeScript:** `closedFunctionNames`, `CLOSED_FUNCTION_NAMES`, `dispatchClosedFunction`, `ClosedFunctionError`, `ClosedFunctionErrorCode`, `interpLinear`, `interpBilinear`, `searchsortedFirst`, `validateInterpAxis` and `validateSearchsortedTable`. The document types lose `function_tables` and the expression-node fields above.
  - **Go:** `ClosedFunctionNames`, `EvaluateClosedFunction`, `IsClosedFunction`, `ClosedFunctionError`, `OpFn`, `OpTableLookup`, `FunctionTable`, `FunctionTableAxis`, `FlattenedFunctionTable`, `EsmFile.FunctionTables`, the expression-node fields `Table`, `TableAxes`, `Output`, `Manifold`, `Label` and `Arg`, and the `Code…` constants of the removed diagnostics.
- **Record axes replace `records_per_sample`** (esm-spec §8.5.1, rewritten; §8.3). How many records a data-fed parameter receives is now said by its **record shape** alone: its declared `shape`, or for a shapeless parameter the declared `shape` of each `param_to_var` target it feeds. It receives the two records that bracket the query time exactly when that shape begins with a **record axis**, an `interval` index set marked `"records": true`; otherwise it receives one. An ordinary size-2 interval or a two-member categorical gives one record.
  - **Now refused:** a document that writes `records_per_sample: 2` (on `from` or on the source's `temporal`) over a plain size-2 first axis is `records_per_sample_invalid`. Fix it by adding `"records": true` to that axis. There is no version gate and no implied record axis. A written `1` over a record axis is refused the same way.
  - **Deprecated, removed at esm 3.0.0:** `from.records_per_sample` and `temporal.records_per_sample` are checked, not obeyed. A document that writes either loads with one `deprecated_records_per_sample` warning listing every place it is written; `deprecated_records_per_sample_sites` (TypeScript `deprecatedRecordsPerSampleSites`) returns that list in every binding.
  - **New diagnostics:** `record_axis_invalid` (a record axis whose size is not 2), `record_axis_misplaced` (a record axis anywhere but first in a data-fed record shape, or targets that disagree) and `record_axis_time_invariant_source` (a record axis on a source with no `temporal.start`). Validation checks every record shape it can see; `flatten` checks again after `coupling_import` expansion.
  - `loader_fields` still reports `records_per_sample`, now the count the shape gives, so EarthSciIO and EarthSciIntegrator need no change. `providers_from_document` (Julia, Rust, Python) refuses a parameter whose record shape depends on a target the document it is given does not show yet.
  - **Rust:** `IndexSet` has a new public field `records: Option<bool>`; code that builds it literally must set it. TypeScript keeps `effectiveRecordsPerSample` as a deprecated export.
  - `"records": false` and an absent `records` are the same declaration at a mount, template-import or rename merge in all five bindings; `true` against either is `subsystem_index_set_conflict`. Fixtures: `tests/conformance/records_per_sample/` (27 cases).
- **A `faq` must read a shaped variable through `index`** (esm-spec §4.3.1, "Shaped variables inside a `faq` are read through `index`"; §9.6.6; CONFORMANCE_SPEC §5.6.4). A `faq` `expr` or `filter` that reads a variable declared with a non-empty `shape` by bare name, in an elementwise position, is the new error `faq_bare_array_operand`. Each evaluator used to invent its own alignment: the Rust reference evaluator silently ignored such a filter when ranks differed, Python aligned it with the box's last axis (the wrong one whenever two index sets have the same extent), and Julia failed with `E_TREEWALK_UNBOUND_VARIABLE`.
  - `validate()` reports it in all five bindings, on the authored equations of every model and inline subsystem, treating a template application as opaque. Julia, Python and Rust also refuse it at build, on the flattened, template-expanded system after the elementwise lift (below), so a bare name delivered through a template binding is refused too.
  - A loop symbol of the node or an enclosing node shadows the declaration. The variable an observed or recurrence definition defines is left to `observed_cycle` / `recurrence_not_wellfounded`; a derivative's state read bare (`D(y)` with a bare `y` in the body) is refused.
  - As defence in depth, Rust's per-cell filter latches `E_TREEWALK_FILTER_UNALIGNED` for an unaligned filter array instead of including the cell, and Python's gated whole-array tiers decline a mask of the wrong rank.
  - Fixtures: `tests/invalid/faq/bare_array_operand_{filter,derivative,subsystem,beside_template}.esm`; positive control `tests/conformance/faq_pointwise_filter/fixtures/indexed_filter_two_outputs.esm`.
- **A coupling entry of `type: "event"` is refused at build** with `unsupported_construct` (esm-libraries-spec §2.5.13), unless its class is stripped (below). Every executing binding's build used to drop such events silently.
- **An `ic` that reads a state is refused at construction** with the new code `ic_reads_state` (esm-spec §11.4.2), naming the target, the state and the chain of observeds that reaches it: `ic(R.v) reads 'R.g', which reads 'R.u', a state`. A build never evaluates it with the state at a placeholder value. Rust used to fail at the solve; `validate()` reports nothing new.
- **An `ic` right-hand side is evaluated at the run's start, `t0 = tspan[0]`** (esm-spec §11.4.2, new; CONFORMANCE_SPEC §5.56). `t` there is `t0`, not 0: Rust's build-time evaluator used to fix time at 0, so an `ic` that reads `t` on a run that does not start at 0 now gets a different value. Data-fed parameters are read at `t0` too, not at `sample_time` (esm-libraries-spec §2.5.2), and a `remake` with a new `tspan` re-evaluates the `ic` (§2.5.5). What an `ic` may now read is under "New".
- **Rust and Julia `flatten` write the elementwise lift into the flattened equations** (esm-spec §9.6.11, "A flattened system keeps its applications' meaning on the wire"; esm-libraries-spec §4.7.5). A template application that binds an array to a scalar parameter is written as the per-cell `faq` the build produces, with loop symbols `_p0, _p1, …`, so a flattened system written out and read back means the same system. Before, such a system read back was refused with `faq_bare_array_operand`. Rust and Julia write the same bytes (`tests/conformance/flatten_wire/`). The pointwise lift (esm-spec §10.5) now also reads at the cell every operand that is an array on the flattened system, including a variable whose shape is inferred rather than declared; it used to leave such an operand bare. Python's flatten is unchanged.
- **Rust: new public fields.** `ProblemOptions` gains `observed_cone: Option<Vec<String>>` and `strip: StripSet`, and `FlattenMetadata` gains `bound_inputs` (not serialized). `ExpressionNode` gains `template_origin`, load provenance that is never serialized. A struct literal that does not end in `..Default::default()` must set them; `IndexSet` (above) has no `Default`.
- **Julia: a scalar parameter fed more than one value is refused** with `E_TREEWALK_UNSUPPORTED_SHAPE`, whether declared `shape: []` or reaching a build with no shape. It used to be read silently as 0.0 or as one of the values. A data-fed parameter declared with no `shape` instead adopts its data's shape, one anonymous index set per axis, as in Rust.
- **Julia: recurrences are refused on three routes.** `compiler = :mtk` refuses a recurrence definition with `compiler_refused_rule` instead of handing ModelingToolkit an algebraic system. A range-restricted program (`halo`, `restrict`) refuses a recurrence along a decomposed axis with `range_global_locality`; it used to loop forever. A lane program refuses one by name.
- **The dimensionless-literal error is deferred.** The bare-literal rule stays a warning at esm 2.0.0. The spec, CONFORMANCE_SPEC and every binding's warning text now say the error arrives in "a future version of EarthSciAST", not "the next major esm version" (esm-spec §4.8.6).

## New

- **A template applied over an array argument is elementwise** (esm-spec §9.6.11, new). A template parameter the body uses as an `index` base (or passes to one) is array-role; every other parameter is scalar-role. An application that binds an array to a scalar-role parameter is evaluated per element, each element bit-identical to the scalar application, with array-role arguments passed whole. This is what `fn interp.*` did with an array query.
  - Whether an argument is an array is decided on the flattened system, after coupling, so it covers a scalar parameter of a 0-D component that a `variable_map` feeds a gridded field.
  - Several array arguments align by index-set name (§4.3.4): a `[lev]` column replicates over a `[lon, lat, lev]` field. Arguments over unrelated index sets, an argument outside the declared target shape, and an anonymous array (`const` literal, `reshape`) in a value position are `array_shape_mismatch`, decided at build.
  - Julia, Rust and Python implement it as a lift at build; TypeScript and Go do not evaluate. Fixtures: `tests/conformance/template_array_args/` (nine fixtures plus the coupled pair). Every case here failed in every build of 0.10.0.
- **Recurrence groups** (esm-spec §4.3.1.2, new; CONFORMANCE_SPEC §5.19.5). Several array observeds, each defined by its own `faq` over one shared frame, may read one another and themselves at earlier positions along one shared axis, or at exactly the cell being written in an acyclic order. They used to be an `observed_cycle` whatever their lag.
  - A group is a strongly connected set of two or more array observeds whose internal edges are all `index` reads, at least one offset. A cycle of same-cell gathers only, a scalar member or a bare-read edge stays an `observed_cycle`.
  - A peer read must be provably strictly earlier or exactly the current cell; straddling or unprovable peer lags are refused. Members whose `output_idx`, ranges or recurrence axis differ are the new code `recurrence_group_axis_mismatch`.
  - Evaluation is defined as the single-variable recurrence of the members stacked on a member axis, so order, fail-closed reads and precision carry over. All five validators check groups; Julia, Python and Rust evaluate them.
  - Fixtures: `tests/conformance/recurrence/` 13–17 and six new cases in its `rejections.json`.
- **A recurrence may be evaluated a slice at a time** (esm-spec §4.3.1.1 point 4, "Slices"; CONFORMANCE_SPEC §5.19.2), on three conditions: slices complete in ascending order, each cell keeps the sequential sweep's operations with no reassociation or fused multiply-add, and a self-read of the current or a later slice faults. Recurrence fixture 10 pins this, and 11 and 12 pin fail-closed faults; the inline-test runner gains `expected_fault`, and CONFORMANCE_SPEC §5.38.2 gains an `exact` tolerance class (bit identity). Julia's `BuildInspection` gains `recurrences` (`RecurrenceInfo`: `var`, `axis`, `max_lag`, `lag_proven`, `slices`, `cells`), matching Rust's, and its `TreeWalkError` gains a `rule` field.
- **What an `ic` right-hand side may read** (esm-spec §11.4.2; CONFORMANCE_SPEC §5.56). Besides literals, `const` data, coordinates and parameters, it may read `t` (bound to `t0`), every data-fed parameter at the value its provider gives at `t0` (else its declared default), caller `const_arrays`, and every observed, scalar or array, built only from these. Julia, Python and Rust implement it; Rust's coupled build now gives `ic`s the build-time observed scope, which only its single-model build used to. Rust's `initial_state(prob)` samples the providers an `ic` reads at `t0` without moving the Problem's forcing. Fixtures: `tests/conformance/ic_at_start/`.
- **Strip and expose** (esm-libraries-spec §2.5.13; CONFORMANCE_SPEC §5.57; API_SPEC §5.8). `esm_problem(…; strip)` takes any of `continuous_events`, `discrete_events`, `parameter_updates` and `algebraic`. Each named class's constructs are removed, the rest builds unchanged, and `stripped(prob)` returns the removed constructs, flattened and namespaced, with the same canonical JSON in Julia, Rust and Python. Classes not named are still refused, and Wiener noise is never strippable.
  - Algebraic unknowns that stripped implicit equations read move from `u` to a separate vector `z`, with a `z_layout` and a `z0` warm start; residuals are `lhs - rhs`.
  - `solve` / `init` on a stripped Problem raise `stripped_problem_not_solvable`.
  - `compile_kernels(prob, specs)` (Julia, Rust) compiles JSON kernel specs (`observed`, `expr`, `residual`, `condition`, `update`, `affect`, `assign`) into kernels with the arguments `(out, u, z, p, t, dt)` plus a workspace and forcing set, sharing the public right-hand side's parameter vector and compiler. Python's `compile_kernels` raises `compiler_unavailable`. New codes: `kernel_output_unresolved` and `affect_reads_post_value`.
  - New API: Julia `stripped`, `is_stripped`, `StrippedConstructs`, `compile_kernels`, `KernelSet`, `kernel!`, `kernel_workspace`, `kernel_layout`, `z_layout`; Rust `ProblemOptions::strip`, `StripSet`, `stripped`, `StrippedConstructs`, `compile_kernels`, `KernelSpec`, `KernelSet`, `Kernel`, `KernelWorkspace`; Python `strip=`, `stripped`, `is_stripped`, `StrippedConstructs`. Go and TypeScript register the three codes. Fixtures: `tests/conformance/strip_and_expose/`.
- **Rust: `esm simulate --observed` evaluates only what it is asked for.** On a document with nothing to integrate, the build evaluates only the requested observeds and every observed they name, transitively, instead of every observed in the document; fields in the cone are bit-identical. A model with state is never pruned. The library option is `ProblemOptions::observed_cone`. An `--observed` name that matches no declared variable (CONFORMANCE_SPEC §5.17.4) is now refused right after load, before any data is read.
- **Julia: `esm_problem(…; program_build = true)`** builds the Problem's right-hand side once as its whole-model program, and `rhs_program(prob)` returns that program instead of flattening and lowering the model a second time. With the keyword off nothing changes. With it, `materialize_out` and non-native compilers are refused, and externally fed parameters are classed `:forcing`, so `remake(prob; p = …)` refuses them.

## Performance

- **Template forms of the removed ops compile fast** in Julia native and the Rust tape. Both recognise the comparison-count shape over unsorted or derived keys, sort a copy once at build and binary-search it; Rust scans short windows without branching. Julia fills an ungated array observed that reduces only build constants once at setup. Both compile a `distinct` key and filter once instead of walking the JSON per point. The Rust tape computes repeated build-time work once and runs straight runs of scalar instructions as one block, and Julia expands each template once into a skeleton shared by its call sites. Every rewrite gives the same bits as the expansion it replaces. Both XLA lanes now compile every template family. One exception: in Rust, setting up an overlap-area template gated by an overlap join is much slower than the removed built-in op was (per call is unaffected; issue #689).
- **Rust: a folded tuple-list contraction is walked once** instead of up to three times, folding chunks as it lists tuples, with less per-tuple and per-cell overhead. Results are bit-identical.
- **Julia: less memo and allocation churn in the affine box lowering**, which spent most of a large build in garbage collection. Generated code is unchanged.
- **Julia: a very large generated right-hand side carries its split sub-functions by value.** Above 100,000 emitted expression nodes, each sub-function is compiled on its own, which shortens the first call and lowers peak memory for very large models; smaller functions are unchanged. By-value calls no longer box their arguments, so steady-state `rhs!` allocates nothing. `ESS_CODEGEN_SPLIT_TRANSPORT=value` or `=definition` overrides the size rule.

## Dependencies

- **Rust:** `s2rst` is dropped and `ryu` is a direct dependency. **Julia:** the GeometryOps, GeoInterface, SortTileRecursiveTree and Extents weak dependencies are dropped; `SHA` and `Serialization` become runtime dependencies. **Python:** the `geometry` extra (`spherely`) is gone.
- Dependabot updates for the TypeScript (`rollup`, `vitest`), Rust (`jsonschema` 0.61 among others) and Python (`ruff`, `hypothesis`) groups.

## Other changes

- **Rust: a decimal tie is written with the even last digit** (CONFORMANCE_SPEC §5.5.3.1 rule 2). `canonical_json` and the display printers used to write the upper of two shortest decimals that both read back as the double, so Rust's canonical bytes differed from every other binding's on such values. They now match; the display printers also no longer write a value that does not read back. Fixture: `tests/conformance/canonical/float_ties.json`.
- **Julia: an announced forcing write reaches the discrete-cadence caches.** After a direct write to a live buffer and `notify_forcing_refresh!`, `f!` read the raw forcing at its new value but derived state-free fields at the old one, so `f!` and `rhs!` of the same Problem disagreed. The caches now refill when the forcing epoch moves.
- **Rust native builds an unshaped `ifelse` whose array branch's shape is known only at build** (esm-spec §4.3.4, rewritten to one reading: the shape is decided at build from operand shapes). A gather from a `const` table or a count `faq` with no output index counts as a scalar, so such an observed is promoted at build instead of refused with "branch value boxes differ". An unshaped data-fed parameter takes its data's shape.
- **Rust: inline tests can assert on a field a pointwise lift evaluates over a grid.** `coords`, `reduce`, element and bare assertions on a lifted 0-D variable used to error; the axes now come from the build. A bare pointwise assertion on such a variable gets a diagnostic naming the lift.
- **Rust: a periodic subscript of ±inf or a huge value** no longer overflows (a panic in debug builds, a wrong residue in release).
- **Rust and Julia: an array `faq` nested under an elementwise operator** (`D(q[f]) = faq(…) - q[f]`) is read at the current cell. Rust's reference evaluator used to read it as NaN and Julia failed with `E_TREEWALK_UNBOUND_VARIABLE`. Rust refuses a nested box that does not match with `E_TREEWALK_NESTED_BOX_MISMATCH`.
- **Julia: `@aliasscope` is removed from the native emitter.** On Julia 1.11–1.13 it let LLVM move a load ahead of a store to the same element, which gave wrong derivatives on Julia 1.12.6 for some scalar programs. Small kernels are slightly slower.
- **Julia: a range-restricted program sweeps a recurrence over its own block.** A tile used to sweep the whole frame, writing outside the block and corrupting memory.
- **Julia: an authored overlap join is applied by the interpreter**, as CONFORMANCE_SPEC §5.5.6 requires; its construction-time sweep used to skip the clause. A template call's bindings shadow the loop symbols the template body binds at flatten, as in Python, Go and TypeScript. A top-level `{"ref"}` mount marks its template expansions as applications, as the subsystem mount already did.
- **Rust and Go `validate()` walk inline subsystems** for the `faq` checks, and Go reports `ragged_values_not_gathered` inside one.
- **Python: bare provider keys** (`F` rather than `H.F`) now reach discrete providers; the run used to fall back silently to the default. A failed construction-time segment seed is no longer kept as a seed. A coupling event's `name` survives load and save.
- **Rust and Julia `flatten` qualify an event affect target `Sub.x`** (a subsystem of the declaring top-level component) like a read of the same name, `M.Sub.x`.
- **Python and Rust parenthesize a logical `or` passed as a function argument** in display, as `tests/display/RENDERING_CONTRACT.md` requires.
- Python, Julia and the Python reference harness class a template call by its bindings for cadence, as Rust did. Pushdown detection in Python and Rust resolves a component's template imports, so a cell factor read through a template binding is lifted as Julia lifts it.
- Benchmark harnesses generate their `.esm` inputs at run time; no generated document is committed. The Go race-enabled test run has a 20-minute timeout in CI.
