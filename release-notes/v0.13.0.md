A breaking release. The `.esm` format moves from esm 2.1.0 to **esm 2.3.0** in two steps. Neither step changes JSON on disk, and every 2.1.0 document still loads. But **esm 2.2.0 changes what some coupled documents mean**: the pointwise lift now applies whatever route brings a grid to a 0-D system, so states that used to be silently evaluated at one element become per-cell arrays. **esm 2.3.0 deprecates `neg` and `pow`**, and it fixes a canonical spelling for units and numbers. Documents can now also be written as **Markdown or Typst source documents**. The Rust binding reads and writes both; the other bindings follow in a later release. The `esm` command-line tool is now its own crate, `earthsci-ast-cli`, and can run `esm simulate` on EarthSciIntegrator as well as diffsol.

## Breaking changes

- **The pointwise lift reaches every route (esm 2.2.0; esm-spec §10.5, esm-libraries-spec §4.7.5; issue #715).** The spec always said that under pointwise lifting, the default, "the 0-D system is evaluated independently at each grid point". But the bindings lifted a scalar state only when an `operator_compose` with an explicit `lifting: "pointwise"` merged an operator `makearray` into its equation. On three other routes, Rust silently evaluated the state at one element of an array right-hand side:
  - a pointwise `variable_map` feeding a shaped field into a 0-D model;
  - an `operator_compose` whose operator is written elementwise rather than as a `makearray`;
  - species left out of a partial `translate`.

  Now a scalar state whose merged right-hand side is an array is lifted onto that array's index sets, together with every scalar state of its top-level component. The search repeats across components until nothing new is lifted. The `makearray` route behaves exactly as before.
  - **What to check:** an inline-test assertion on such a state with no subscript (for example `Mech.A`) now addresses an array. Assert per cell (`Mech.A[2]`) or through a `reduce`.
  - **Now accepted:** per-cell `initial_conditions` keys and array `ic` equations on a lifted state. They used to be rejected.
  - **New refusal:** a component whose states would land on two different grids fails with the binding's dimension-promotion error (`DimensionPromotionError`).
  - **`lifting: "mean"` and `"integral"` are refused at build.** No binding evaluates either reduction. A build used to read the raw array at one element, which is a silent wrong value. Every binding that builds a runnable problem (Rust under both compilers, Julia and Python) now refuses such an edge with `unsupported_construct`, naming the edge and the kind. This includes a system flattened beforehand and then built. Validation and flattening are unchanged, and `broadcast` is not affected. Neither these kinds nor `broadcast` trigger the lift.
- **`neg` and `pow` are deprecated (esm 2.3.0; esm-spec §4.2, "Deprecated ops").** A loader rewrites `neg(x)` to unary `-`, `pow(x, n)` to `^`, and a `broadcast` with `fn: "neg"` to `fn: "-"`. It warns `deprecated_op` once per document, listing every rewritten node by its JSON pointer. The reference-preserving emit path applies the same rewrite, so neither spelling reaches an emitted document. Evaluators still accept both operators in trees built in code. Replace them with `-` and `^` to silence the warning; they become `removed_op` in a later major.
- **Canonical form changes.** These matter to a consumer that compares canonical forms byte for byte:
  - Every `units` string is written in the canonical unit spelling (esm-spec §4.8.2; the Lean definition `Esm.Units.canon` is the authority). Factors are sorted, there is at most one `/`, exponents are exact rationals, and Unicode is normalized: `µg/m³` becomes `ug/m^3`, and `mol/mol/s` becomes `mol/(mol*s)`. `""`, `"1"` and `"dimensionless"` all become `"1"`.
  - A `const` whose units spell `1` loses them. A scalar one becomes the bare literal, so `x + const(0, "dimensionless")` canonicalizes to `x`. A consequence: `validate(canonicalize_document(doc))` can skip a unit check that `validate(doc)` makes.
  - `-(0, x)` no longer collapses to `-(x)`, since the two differ when `x` is +0.0.
  - Numbers are written in their canonical form (CONFORMANCE_SPEC §5.5.3.1), and `canonicalize_document` also applies the `neg` / `pow` rewrite.
- **Unit strings that used to resolve by accident are refused.** A superscript minus only counts directly before superscript digits, so `s⁻1` and `m²⁻¹` no longer resolve; TypeScript used to read `m²⁻¹` as `m^-21`. TypeScript also no longer resolves `toString`, `constructor` and other object-prototype names as units.
- **Rust: the `esm` binary moved to the new `earthsci-ast-cli` crate** (`pkg/earthsci-ast-rs/cli`). Install it with `cargo install earthsci-ast-cli`. The library's `cli` feature remains as a no-op, so manifests that name it still resolve.
- **earthsci-narrative reads pages through the core Markdown reader.** Each docs page is now a core Markdown document. The model, declarations and equations use core syntax, while tests and plots stay narrative `esm-` directives. An equation's label goes after its closing `$$` as `{#id}`. The narrative's own element format is internal now.

## New

- **Markdown and Typst source documents** (esm-spec §1.2). A document can be written as a Markdown file (`.md`, with LaTeX math) or a Typst file (`.typ`), as well as JSON. The commented Lean source under `formal/Esm/Document/` specifies both formats, and it is published as the "Document formats" chapter on earthsci.dev. 195 golden cases in `tests/conformance/document_format/` (CONFORMANCE_SPEC §5.58) are generated from the Lean model and checked against it in CI.
  - **Rust** implements both, ported from the Lean model file by file: `parse_markdown`, `parse_typst`, `parse_document`, `print_markdown`, `print_typst`, `print_document`, `print_math` and `DocumentFormat`, with the new diagnostic code `parse_error`. Every `.esm` under `tests/` round-trips through both formats. Over those 1,412 documents, the Rust and Lean printers agree byte for byte, and so do the canonical forms and parses.
  - Julia, Python, TypeScript and Go do not read or write these formats yet.
- **`canonicalize_document`** (`canonicalizeDocument` in TypeScript, `CanonicalizeDocument` in Go), in all five bindings. It takes a decoded document and returns a copy with every `units` and `default_units` string respelled, deprecated operators rewritten and numbers canonicalized. It skips free-form objects (`metadata`, `x_esd`, `attrs`, `config`, `reader_options`), and it does not mistake a variable named `units` for a units string.
- **`esm simulate --backend integrator`.** A build of `earthsci-ast-cli` with the `integrator` feature can run `esm simulate` on [EarthSciIntegrator](https://github.com/EarthSciML/EarthSciIntegrator) 0.1.0 as well as on diffsol, the default. Without `--run-config`, the integrator plans its own `"auto"` schedule inside fixed macro steps of `--dt`; `--plan-dir` keeps the plan. `--observed`, `--compiler` and `--no-count-fold` are refused under this backend, and `esm test` and the simulate benchmark stay diffsol-only. The binaries on the GitHub release are built with diffsol only.

## Other changes

- **Rust: faster evaluation of large relational documents.** Every result is bit-identical; only the cost changes.
  - A composite join key over integer columns is packed into one integer, and the smaller side of a join is bucketed.
  - On-gates over the same pair of symbols merge across join clauses.
  - A build-time observed whose rows repeat is evaluated once per distinct row and gathered back. `ESS_ROW_DEDUP=0` turns this off.

  On a port of the MOVES emissions model, the largest run measured went from about 29 minutes and 36 GB to about 7 minutes and 12 GB.
- **Lean formal model:** the document-format codecs and printers gained fixes found while picking the golden cases. Typst `upright(e)^x` is accepted. Named template arguments may come in any order, and duplicate names are refused. A Markdown reaction table with a rate column is refused instead of being silently dropped as prose. `esm-lean canon` reads a decimal as the nearest binary64.
