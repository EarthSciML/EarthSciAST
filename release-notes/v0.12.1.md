A patch release with two fixes to the Rust build, and more of the formal model's groundwork for document source formats. The `.esm` format stays at **esm 2.1.0**, and Julia, Python, TypeScript and Go have no code changes.

## Fixes

- **Rust: the elementwise lift of a template application no longer depends on equation order** (issue #714, esm-spec §9.6.11). An unshaped variable got its shape only once its definition had been visited. So an equation that read it, and came earlier in the order, was wrapped while that shape was unknown. Its operand stayed bare inside the lifted `faq`, and the build refused the document with `faq_bare_array_operand`. The same document built fine without the template. Shapes are now settled in dependency order before any equation is wrapped. A shape mismatch is reported only against the final shapes, never against a provisional one. The build's shape view after the lift infers in the same order. The issue's documents now build under both compilers and pass their assertions.
- **Rust: overlap join gates whose sides are ring stacks are now driven** (CONFORMANCE_SPEC §5.5.6). A gate with one `[pos, verts, coord]` ring stack per side, the form the `overlap_area_planar` regridding templates use, was never resolved. The interpreter walked the full source × target product. The native compiler refused large regrids such as a 459×299 → 13×7 grid with "a rank-0 output's promoted box is too large". The gate now resolves, so both compilers visit only the candidate pairs. The scalar parameters that the rings are computed from are baked at build, as parameters that feed an `on` key column already are. Rust results agree with Julia's to rounding. Julia and Python already handled this form.
  - The interpreter's overlap-gate cache is now keyed by the envelope factors' contents, not just their names. Before, a second build with the same ring names and different geometry silently reused the first build's candidate pairs.
  - An envelope factor that reads a state, the time, or an input refreshed from outside the model is now refused at build by both Rust compilers with `E_TREEWALK_JOIN_OVERLAP`, as §5.5.6 requires and as Julia does. Before, only `native` refused it. Changing a parameter that feeds a ring stack through `remake` is also refused now, as it already was for a parameter that feeds an `on` key column.
  - New conformance fixture: `value_invention_geometry/overlap_gated_regrid_ring_params_ode`.

## Other changes

- **Formal model: LaTeX and Typst math grammars, with proven round trips** (Phase 2 of the document-source-formats plan). For every symbol table and every well-formed expression, parsing the printed LaTeX or Typst gives back the original expression. All 8,446 well-formed expressions in `tests/` round-trip through both grammars. Lean only, with no binding changes.
