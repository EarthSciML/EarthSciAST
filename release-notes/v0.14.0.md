A breaking release for the binding APIs. The `.esm` format is unchanged (still **esm 2.3.0**), and every document that loaded under 0.13 still loads. The plain-text expression surface is retired in all five bindings: expressions as text are now only document math, LaTeX in Markdown and Typst in Typst. **Markdown and Typst source documents** can now be read and written in all five bindings, not just Rust, and a cross-binding gate checks every binding against the Lean model. The node shapes that used to print in the `\esm{…}` escape form now have real math notation that KaTeX renders.

## Breaking changes

- **The plain-text expression surface is removed from every binding (#743).** MIGRATION.md's last section, "The plain-text expression surface is retired", lists every removed function and its replacement, per binding.
  - The plain-text parsers: `parse_expression`, `parse_equation`, `ExpressionParseError`, and TypeScript's reaction text parser `parseReaction`. Use `parse_math` (below).
  - The ASCII, Unicode and old LaTeX renderers (`to_ascii`, `to_unicode`, `to_latex` and their spellings in each binding), their text summaries of models and files, and the helpers only they used. Also TypeScript's `toMathML` and `formatChemicalName`, Go's `ModelSummary`, `ToUnicodeSpaced` and `Fmt*`, Python's `FlattenedEquation.lhs_str` / `rhs_str`, and Rust's `TextRenderable`. Use `print_math`.
  - esm-spec §4.1.1's infix text surface, and the `tests/display` and `tests/conformance/expression_parse` conformance tiers.
- **String display prints Typst math.** `Display`, `show`, `__str__` and `String()` of an expression or equation, and error messages that quote one, now print Typst math. Python's Jupyter display is built on `print_math`.
- **Graph labels.** DOT and Mermaid labels are the names as written in every binding (`O3`, not `O₃`), as Rust already did.
- **Flattened expressions changed shape in Julia, Rust and Go (#743).** The flatten conformance corpus now compares expressions rather than ASCII renderings, which exposed three divergences, now fixed:
  - Julia built a composed or coupled right-hand side as one n-ary `+`. It now builds the left-fold sum of the contributions that the spec defines and the other bindings already built.
  - Rust and Julia now put `output_idx` on a pointwise-lifted operator `makearray`, as Python, TypeScript and Go did (esm-libraries-spec §4.7.5).
  - Go wrote `"args": null` on lifted `faq` nodes. It now writes `[]`.
- **Printed documents changed (#744).** Documents printed by 0.13 still read, but the Markdown and Typst printers now write the new notation below, so printed text compared byte for byte will differ.
- **`esm pretty`** prints Typst by default; `--format markdown` prints LaTeX.

## New

- **Markdown and Typst documents in Julia, Python, TypeScript and Go (#738).** Every binding exports the same seven functions, spelled in its own style (API_SPEC.md §5.1): `print_markdown`, `print_typst`, `print_document(doc, format)`, `parse_markdown`, `parse_typst`, `parse_document(text, format)` and `print_math(expr, names, format)`. A refused text raises the binding's parse error with code `removed_op` or `parse_error`, which is now in every binding's error-code registry. All four ports follow the Rust reader limits (nesting bounds, binary64 range), pinned by `tests/conformance/document_format/limits.json`.
  - TypeScript parsers return plain JS numbers by default. With `{ canonical: true }` they return int and float literal values, and an integer outside the safe range is an exact `bigint`.
  - Julia selects the format with the symbols `:markdown` and `:typst`.
- **`parse_math(text, names, format)`** in all five bindings (#743), the exact inverse of `print_math`. It reads one expression or equation with the document readers' math parser; text whose top is `=` reads as `{lhs, rhs}`. `expression_names(expr)` is now in all five bindings too.
- **Math notation for the shapes that used the escape form (#744),** in all five bindings and the Lean model:
  - `makearray` prints as a bracketed two-column table of values and the regions they fill.
  - An `faq` whose `args` are not exactly the arrays its body indexes shows them as a braced superscript set.
  - Rank-1 and rank-2 array constants print as a matrix whatever their size; more than 10 columns use a LaTeX `array`, since `bmatrix` stops at 10.
  - A template call with no bindings and no known parameter list prints as a bare `\operatorname{name}`.
  - `broadcast`, `reshape`, `transpose`, `concat`, and an `faq`, `makearray` or `const` with no native shape print in a call form with fields after `;`, such as `\operatorname{reshape}(a; \mathrm{shape} = [2, 3])`.

  The escape form is now written only for annotated nodes, non-identifier field keys and a few uncovered shapes, and it is still read. Each new form is read only as the printer writes it. Across the conformance corpus, all 12,764 math pieces render in KaTeX strict mode.
- **Cross-binding document-format gate (#741).** For every corpus document (1,415), both formats, and every printer and reader, the five bindings and the Lean model (`esm-lean`) must agree: each canonical form and printed text matches Lean's byte for byte, and each reader reads every printer's text back as Lean's canonical form. Run it locally with `scripts/run-document-format-gate.py`.
- **Tools:** `esm convert --to` takes `markdown` or `typst`. earthsci-narrative's `eq` elements take Typst `math:`, and `::esm-example` reads LaTeX. The Typst plugin renders expression JSON to `{latex, typst}`.

## Fixes

- **Julia: flatten no longer hangs on deep shared templates (#737).** The elementwise-lift walk visited template expansions as trees, so a chain of templates each referencing the one below twice cost 2^depth visits. EarthSciIntegrator's 32-deep chain never finished flattening. Each shared expansion is now visited once.
- **Rust: native builds an unshaped `ifelse` whose array arm reads a calendar-template scalar (#739, issue #664).** `compiler: Native` refused models such as NEI2016 emissions, whose `ifelse` arms multiply by `hour(t)` or `month(t)` from `esm:std/calendar.esm`, with "branch value boxes differ under a runtime scalar condition". The `ifelse` shape rule now handles those arms, as the interpreter already did.

## Other changes

- **CI (#742):** runs of a closed or merged PR are cancelled, and a PR that changes only one binding runs only that binding's suites.
